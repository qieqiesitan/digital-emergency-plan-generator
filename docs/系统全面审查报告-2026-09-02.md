## 二、高危问题（建议立即修复）

### P0-1 管理类接口缺少角色校验，普通用户可越权操作【安全】

- **现象**：用普通用户 `test@test.com`（role=user）的 token 直接请求：
  - `GET /api/v1/admin/users` → **200**，返回全部用户列表
  - `GET /api/v1/admin/roles` → **200**
- 对应前端表现：普通用户登录后，侧边栏「设置」里能看到用户管理、角色管理、系统配置等页面，并能对超管账号执行"编辑/重置密码/删除"操作（按钮均可用）。
- **风险**：任何注册用户都可以枚举全部账号、重置他人（含超管）密码，等同于权限体系失效。
- **建议**：后端所有 `/admin/*` 路由加角色依赖（如 `require_role("admin")`）；前端菜单同时按角色隐藏（但绝不能只依赖前端隐藏）。

### P0-2 法规管理模块整体故障，页面无限 loading【功能】

- **现象**：「设置 → 法规管理」打开后永远停留在转圈状态，无任何错误提示。
- **根因**（后端日志实锤）：`GET /api/v1/regulations/stats/data` 返回 500 —
  `chromadb.errors.NotFoundError: Collection [5f949f5b-…] does not exist`（ChromaDB 向量集合不存在，可能是数据卷重建后未初始化）。
- **双重缺陷**：① 后端未捕获异常直接抛 500；② 前端无超时/错误兜底，用户只能干等。
- **建议**：后端对该接口做 try/except 并返回"法规库未初始化"的业务错误码 + 初始化入口；前端所有数据加载统一加失败态（错误提示 + 重试按钮）。

### P0-3 宿主机端口冲突：`wslrelay.exe` 与 Docker 同时占用 5173/8000【环境】

- **现象**：`localhost` 访问 5173/8000 时，IPv6（::1）流量被 WSL 残留转发（wslrelay.exe，PID 27020）劫持，返回 404/空响应；只有 `127.0.0.1` 才稳定到达 Docker。
- **影响**：开发者用 `localhost:5173` 访问 dev server 会出现"时好时坏"的灵异问题，排查成本极高（本次审查也踩中）。
- **建议**：在 WSL 中清理失效的端口转发（`wsl --shutdown` 或检查 WSL 内是否有旧 dev server 常驻）；团队文档统一约定用 `127.0.0.1` 或 8082 入口。

## 四、美观性（系统性设计审查）

> 方法：① 读取 `tailwind.config.ts` 提取设计令牌基准；② 脚本遍历 15 个页面抓取全部按钮/输入框/表格/标签的 computed style 并聚合（共采样 486 个按钮、22 个输入框、9 张表、90+ 标签）；③ 关键区域 2 倍放大截图逐页复核。**核心结论：代码里同时存在 Ant Design 默认主题和 tailwind 自定义令牌两套设计系统，实际渲染以后者从未生效、前者为准，导致全站样式双轨漂移。**

### 4.1 设计系统层：令牌与实际渲染脱节（本次最重要的发现）

| # | 维度 | 证据 | 问题 |
|---|---|---|---|
| A1 | **主色双轨** | tailwind 令牌 `primary-600=#1A56DB`；实测全站 17 个主按钮**全部**渲染为 `rgb(22,119,255)=#1677FF`（antd 默认蓝），令牌色**零使用** | tailwind 里的色板是死代码。改主题只改 tailwind 不会生效，两处必须同步 |
| A2 | **圆角双轨** | 令牌 `6px`；实测按钮 4px×278 次 vs 6px×200 次混用；输入框 0px×17 vs 6px×4 | 同一页面里圆角不统一（antd 组件 4px、自绘元素 6px），细看有毛糙感 |
| A3 | **字体未加载** | 令牌首选 `Inter`；实测 `document.fonts` 为空（未加载任何 Web 字体），body 字体栈是 antd 默认 `-apple-system, Segoe UI, Roboto…` | Windows 上英文渲染为 Segoe UI、中文走系统回退，与设计稿（Inter+苹方）不一致；数字缺少等宽/表格化处理 |
| A4 | **字号体系漂移** | 令牌 7 级（34/28/22/17/16/14/12）；实测以 14/12px 为主（antd 默认），页面标题实为 **20px/600**（不在令牌内），另散落 13px、13.333px、15px、24px/400 等非令牌值；驾驶舱出现 **8/9.5/10/10.5/12.5px**，隐患页有 **9px** | 字号没有统一阶梯，页面标题各写各的；<10px 的文字在普通显示器上几乎不可读 |
| A5 | **表头与阴影** | 表头背景实测 `#fafafa`（antd 默认）而非令牌 `#F9FAFB`；卡片阴影实测 antd 默认 `0 2px 0 rgba(0,0,0,0.02)` 而非令牌 `shadow-card` | 与 A1 同源：视觉基准实际由 antd 主题决定，应改为显式配置 antd ConfigProvider theme 令牌，让两份配置合一 |
| A6 | **悬浮球色** | 悬浮球阴影 `rgba(99,102,241,0.15)` = 令牌 info 紫 `#6366F1` | 全站主色为蓝，唯一常驻的全局控件却是紫色，色彩语义冲突（这也是它看起来"突兀"的根因） |

**修复建议（一处改动全局收益）**：在 antd `ConfigProvider` 的 `theme.token` 里把 `colorPrimary`、`borderRadius`、fontFamily 设置为与 tailwind 相同的值（或反向把 tailwind 改成 antd 值），并让页面标题统一走令牌字号。删除 tailwind 中未生效的死配置。

### 4.6 美观性优先修复建议

1. **合并设计令牌**（A1-A5，一处 ConfigProvider 改动全局生效，性价比最高）；
2. **加载字体 + 收敛字号阶梯**（A3、A4，消灭 <12px 文字和 13.333px 这类散点值）；
3. **驾驶舱统一浅色或全站提供主题切换**（A7）；

5. 表格列宽/溢出专项整治（A16、A17）；移动端 TabBar 安全间距（A15）。

## 五、易用性问题

### 5.1 空状态与失败态（本次遍历中最普遍的问题）

- **空状态普遍只有一行灰字**：企业预案列表"暂无预案"、排查计划"暂无排查计划"、排查任务"暂无排查任务"、管控清单"暂无管控清单数据"——都没有引导按钮（如"立即新建""先去添加风险点"）。做得好的参考：可视化总览（有插图）、组织与人员管理（"暂无成员，可 Excel 导入或手动添加"）。**建议全站空状态统一为"插图 + 说明 + 主操作按钮"三件套。**
- **失败态几乎为零**：法规管理 500 卡死（P0-2）、onboarding 缺参只显示"请先选择企业（缺少 enterprise_id 参数）"且无可点击入口。
- **技术语言直接暴露给用户**：`缺少 enterprise_id 参数`、隐患公示里的路由模板 `（/h/:token）`、提示词管理分类列显示英文 `emergency_diagram`。建议面向用户的文案一律去技术化。

### 5.2 导航与信息架构

- **同名卡片无法区分**：预案总览中"中国石油天然气股份有…"三张卡片完全相同（名称截断 + 无其他区分信息），用户无法分辨。"延长壳牌石油有限公司…"同理。建议：名称加 tooltip 全称 + 卡片显示地址/编号等次级区分信息。
- **风险分级管控的二级菜单**：分组标题（数据编辑/成果输出）是灰色小字、与可点击项几乎无视觉差异；"数据编辑/风险树编辑/评估方法"呈灰色像被禁用但无说明；顶部"现有风险图/固有风险图/四象限/分布图优先/数据优先"一组按钮对新用户语义不明。
- **四色图工作台**：工具栏 20+ 个纯图标按钮无文字标签，学习成本高，建议至少加 tooltip。
- **新建/编辑企业**：主按钮"创建企业/保存"出现在"展开全部字段"之前——展开更多字段后按钮悬在表单中间，视觉动线断裂；GIS 区域在按钮之后。建议主按钮固定于表单底部或悬浮底栏。
- **版本历史**：只有 1 条记录时仍显示分页器；无"恢复到此版本"之外的操作说明。

### 5.3 交互细节

- 登录页"记住邮箱"默认勾选，符合预期；密码可见性切换、注册页密码规则提示（至少 8 位含字母数字）都有，好评。
- 导出预览页的"导出前请修复以下问题（红）/质量提示（黄）"分级校验 + "去编辑"跳转是全站体验最好的设计之一，值得作为模式推广。
- AI 配置页有"测试连接"和连接状态条，好；但底部"删除配置"按钮在首屏被截断。
- Chat 页会话列表每项常驻红色删除图标，略显突兀，建议 hover 才显示。

### 5.4 权限可见性

普通用户能看到：用户管理、角色管理、系统配置、提示词管理、法规管理、数据字典管理全部管理功能入口。即使后端修好 P0-1，前端也应按角色隐藏这些菜单（配合 `settings/users` 等路由守卫）。

## 九、交互级测试补充（第二轮，真实点击/输入验证）

| # | 测试项 | 结果 | 说明 |
|---|---|---|---|
| I1 | 登录失败（错误密码） | ✅ 好 | 顶部红色错误条"邮箱或密码错误"，可关闭，规范 |
| I2 | 登录/新建企业空表单提交 | ✅ 好 | 有前端校验提示 |
| I3 | 注册（弱密码+两次不一致） | ✅ 好 | 内联提示"密码至少 8 位""两次密码不一致" |
| I4 | 删除企业 | ✅ 好 | 二次确认弹窗"确定要删除「XX」吗？此操作不可撤销。" |
| I5 | 企业搜索 | ⚠️ 一般 | **需回车才触发过滤，无即时搜索**；行业筛选可用 |
| I6 | 桌面登录页"忘记密码" | ❌ 缺失 | **桌面端没有找回密码入口**；移动端有"忘记密码？请联系管理员重置"。两端不一致，自助找回流程缺失 |
| I7 | Chat / AI 助手（AI 未配置时） | ❌ 差 | **发送消息后显示"（无回复）"，无任何错误提示或"请先去设置→AI 配置"的引导**——用户会以为系统卡死。AI 是本产品核心卖点，未配置时的降级体验必须处理 |
| I8 | 专业模式开关 | ⚠️ 存疑 | 在工作台切换开/关，页面内容几乎无变化（文本量 4883→4947），用户无法感知这个开关的价值和作用范围，建议加说明或在生效页面给出差异提示 |
| I9 | 公开脱敏链接（风险公示） | ✅ 基本好 | 未登录可访问，"公开只读页面 · 数据已脱敏"标识清晰；但**空数据时表头渲染重复两遍**，且日期仍是美式 `9/2/2026, 11:57:00 AM` |
| I10 | 新建预案流程 | ✅ 好 | "选择类型→确认信息"两步向导清晰，类型卡片有适用场景说明；"选择企业"弹窗带搜索+行业筛选 |
| I11 | 悬浮球 | ⚠️ | 确认为"AI 助手"入口（同 I7，未配置时同样无引导）；常驻遮挡问题见 A6 |

**第二轮结论**：基础表单交互（校验、确认、错误条）质量整体不错，主要缺口集中在 **AI 不可用时的降级体验（I7）**、**找回密码入口缺失（I6）** 两个真实用户必踩的坑上。
