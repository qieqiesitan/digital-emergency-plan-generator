# ADR-001：法规上下文统一管道

## 状态
已定稿，实施中

## 目标
风险评估报告、应急资源调查报告、所有类型应急预案逐章生成时，法规条文作为写作纲要注入 prompt，LLM 自然融入正文。

## 不做的
- 不在正文末尾追加引用清单
- 不在前端加法规引用编辑器

---

## 核心设计

### 法规参与方式

| 章节类型 | 法规作用 | 注入方式 |
|----------|---------|---------|
| 编制依据/调查依据 | 直接写入——本章就是列法规的 | 法规名称+文号+施行日期作为数据填入 prompt |
| 技术性章节 | 提供标准——法规规定了本节必须覆盖的维度 | 条文原文作为写作纲要 |
| 管理性章节 | 提供合规要求——法规规定了人员/流程/频次 | 条文要求转为生成指令 |

### 加载策略

- 语义搜索全局排序，按 token 预算（3000 token）从高到低填充
- `index.yaml` 中标记 `mandatory: true` 的法规，条文全量加载不计预算
- 中文约 1.5 字/token，到阈值截断并标注省略

### 调用频次

- **不是每章调一次**，是整份预案/报告调一次
- `build_for_plan()` → 一次语义搜索拿到全量条文，内存缓存
- `get_chapter_context(section_key)` → 纯本地过滤+裁剪，零网络开销

## 实施步骤

### 第一步：修复 _load_articles 文件匹配
- 文件：`regulations/retriever.py`
- 优先用 `index.yaml` 的合规 ID→文件名匹配（已一致）
- 三级 fallback：ID 匹配 → label/code 模糊匹配 → 全文扫描
- 失败打 `logger.error`，不静默

### 第二步：创建 RegulationContextBuilder
- 文件：新建 `regulations/context_builder.py`
- `build_for_plan(plan_type, enterprise_data)` → 一次获取全量
- `get_chapter_context(section_key)` → 本地过滤+token裁剪
- 返回结构体（非拼接字符串）

### 第三步：三个模块统一接入
- 文件：`generation.py`、`risk_assessment_service.py`、`resource_investigation_service.py`
- 替换 `inject_regulations()` 为 `context_builder`
- 更新 system_prompt 去掉「附录」风格

### 第四步：去掉静默吞异常、语义优先
- `context_builder.build()` 异常打 log + 降级通知
- 调用方去掉 `except: pass`
- 语义优先，图谱兜底
