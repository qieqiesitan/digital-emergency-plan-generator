## 一、结论摘要

1. **v1 的 6 个 P0 一条都没修**（逐条复核，见 §五）；v1 结论仍然有效，但已不足以覆盖现状。
2. **新增的 5 个模块带来了更严重的问题**：**34 个新端点没有鉴权**，其中含跨企业读票据、写气体检测、改平台 AI 能力配置等写操作。已用真实浏览器证明：普通用户 A 打开 B 企业的作业票页，能看到 B 的 28 张作业票。
3. **两个新旗舰功能是空壳**：AI 能力注册表（8 条能力、启停开关）没有任何代码读取；LLM 调用统计没有任何埋点——实测发一次真实对话，`llm_call_logs` 行数**没有变化**。
4. **迁移与部署不一致**：容器内只有 41 个迁移脚本、仓库有 46 个，`schema_migrations` 缺 5 条；本地 compose 不挂载 `backend/` 根目录，导致新迁移在本地永远不可见（表/种子是绕过运行器手工生效的）。
5. **两条 v1 缺陷已修掉一条半**：流式截断已改为抛 `LLMStreamTruncatedError`（修好）；超时映射仍是错的——复测显示超时落成 **502 "AI 服务连接失败: AI调用失败: 0"**，不是预期的 504。
6. 基线数据：pytest **1756 passed / 9 failed / 2 收集错误**；新模块定向测试 **217 全绿**；vitest **274 passed**；tsc **0 error**；eslint **246 errors / 20 warnings**（与 v1 基本持平）。

### 2.4 作业票审批流缺陷（安全关键）

| # | 问题 | 证据 |
|---|---|---|
| T1 | **气体检测端点可匿名写入**：`POST /work-ticket/tickets/{id}/gas-tests` 无鉴权、无权限校验，任何人可给任意票追加"新鲜"检测记录 | `work_ticket.py` 该函数仅 `Depends(get_db)` |
| T2 | **审批动作不校验操作人资格**：`act_on_node()` 只校验票状态与动作名，不校验 `user_id` 是否在 `eligible_users_for_node()` 名单里；`sign_policy="any"`（默认）下**任意登录用户点一下 approve 即可推进节点** | `work_ticket_service.py:280-360` |
| T3 | 同上，任意登录用户可 `reject` 任意在批票据（审批拒绝型 DoS） | 同上 |
| T4 | 票详情/列表无鉴权，审批记录、签字人、气体检测全部可匿名读取 | §2.1/2.2 |

> 正向：`validate_before_submit()`（必填项、强制措施确认、动火/受限空间气体检测 + 30 分钟时效）与"法定环节不可删除"（`validate_node_deletion`）实现正确、且有测试覆盖。

### 2.5 数据抽取/导入的安全与滥用面

| # | 问题 | 证据 |
|---|---|---|
| E1 | `POST /extraction/parse-file` 无鉴权、**无文件大小上限**（`data = await file.read()` 全量入内存），可匿名上传超大文件造成内存/CPU 耗尽；返回全文 | `extraction.py`、`file_parser.py` |
| E2 | `POST /extraction/run` 与 `/suggest-mapping` 无鉴权且**直接调用系统级 AI 配置** → 任何人可白嫖企业 AI 额度、刷爆 token 费用 | `extraction.py` 取 `get_system_ai_config(db)` |
| E3 | `POST /ingest/sources` 无鉴权可创建/读取数据源配置（`config` JSONB，含内部地址等） | `ingest.py` + `models/ingest.py` |

> 正向：`IngestSource` 只存 `secret_ref` 指向 `third_party_config`，不存明文密钥；DataHub 只注册了 `major_hazard_unit` / `major_hazard_unit_chemical` 两个目标写入器（可写实体收敛）。

## 三、新模块功能正确性（R2）

### 3.1 AI 能力注册表是"死开关"【实测 + 代码实证】

- 8 条能力已入库（`risk_suggest_objects`、`hazard_grade`、`major_hazard_extract`、`work_ticket_jsa`…），`is_enabled` 全为 true；
- `ai_capability_service.is_capability_enabled()/get_capability()` **全仓库 0 个调用点**（`rg` 仅命中定义处）；
- `llm_client.py` 与各业务服务都不读能力表 → 在管理页把某能力关掉，**对实际调用没有任何影响**；页面上的"模型/提示词可管理"同样没有落点。

### 3.2 LLM 调用统计没有埋点【实测】

```
调用前 llm_call_logs = 4
（发一次真实对话：POST /api/v1/chat → 200，148 字节响应）
调用后 llm_call_logs = 4      ← 没有新增
```

- `llm_telemetry.py` 会写 `LlmCallLog`，但**全仓库没有任何模块 import/调用它**；`ai_usage_stats` 只负责聚合。
- 结论：平台总览/AI 调用统计页在生产上会长期显示 0 或开发期残留数据。

### 3.3 前后端权限不一致（DataHub）

- `frontend/src/utils/menuMap.ts` 把 `/settings/data-hub`、`/settings/data-hub/import` 映射到 `menu:data_hub`（权限码存在，admin 有、user 无）；
- 浏览器实测（user 角色）：两个页面都显示"无权限访问"（前端守卫有效）；
- 但对应 API（`GET/POST /ingest/*`）对匿名完全开放 → **前端锁门、后端没墙**。

### 3.4 重大危险源计算：正向结论

`major_hazard_calc.compute()` 实现的是 GB 18218 式(1)(2)：`S=Σ(q/Q)` 判定、`R=α·Σ(β·q/Q)` 分级，α 表（<1→0.5、1–29→1.0、30–49→1.2、50–99→1.5、≥100→2.0）与级别阈值（100/50/10）与标准一致；`_validate` 覆盖负值/零临界量/非法 β。新模块定向测试 **217 全绿**（含 `test_major_hazard_calc.py`）。
