## 三、本轮新发现并修复的真实缺陷

> 检出方式：摘除 `@ts-nocheck` 后 `tsc -b` 暴露 106+ 处类型错误，逐个人工判断；其中下列条目是**运行时缺陷**而非纯类型问题。部分缺陷由 v3 的浏览器验收未能覆盖（验收只验"页面能打开"，未验"表单能提交""提示有文案"）。

### P0-1 移动端新建/编辑企业无法提交（行业分类没有入口）

- 现象：`EnterpriseForm` 以"字段组件"方式使用 `SelectSheet`（只传 `label/value/options/onChange/placeholder`），但 `SelectSheet` 实际是"受控弹层"，要求 `open`/`onClose`，也没有任何触发按钮。
- 影响：`open` 恒为 `undefined` → 弹层永不渲染 → 用户无法选择行业分类；而表单校验 `if (!values.industry) e.industry = "请选择行业分类"` 会让**提交永远失败且不显示错误提示**（`error` 未渲染）→ 移动端"新建企业"整条链路死锁。
- 修复：重写 `SelectSheet` 为自包含字段组件（自带触发器 + 内部 `open` 状态 + 展示已选值 + `placeholder` 占位 + `error` 文案），并在 `EnterpriseForm` 传入 `error={errors.industry}`。
- 复验：移动端 390 实测"打开选择器 → 选工贸 → 提交成功 → toast 显示'企业创建成功' → 跳转详情页"；截图 `b1-mobile-enterprise-form.png`（可见行业分类字段与"工贸"）。

### P1-1 后端 `PUT /plans/{id}` 丢弃创作风格（前端保存无效）

- 现象：`PlanUpdate` schema 含 `style_preference` / `advanced_prompt_overrides`，但路由只执行 `if data.title is not None: p.title = data.title`。
- 影响：Web 端"创作风格"与"高级模式提示词覆盖"保存后重新打开即回到默认值（静默丢数据）。
- 修复：`backend/app/routers/plans.py` 落库两字段；新增 `backend/tests/test_plan_update_style.py`（2 例，含"只传 title 不清空已有风格"），并做**红-绿验证**（临时禁用修复 → 用例失败；恢复 → 通过）。
- 复验：浏览器实测"点'正式' → 保存 → 刷新 → 弹窗仍选中'正式'"。

### P1-2 前端只写不读：创作风格/高级覆盖回填缺失

- 现象：`PlanEditorPage` 只调 `updatePlan({style_preference})`，从未把 `plan.style_preference` 读回本地状态；前端 `PlanProject` 类型里也缺这两个字段。
- 影响：即便后端已落库，UI 仍显示默认值 → 用户以为"保存失败"（本轮 E2E 首跑正是因此失败，暴露了这一层）。
- 修复：`types/plan.ts` 补 `style_preference` / `advanced_prompt_overrides` 声明；`PlanEditorPage` 增加渲染期回填（含 `mode=advanced` 时恢复高级模式）。

### P1-3 移动端 23 处 toast 调用签名错误（提示条变空白）

- 现象：`showToast("企业已删除", "success")` 等位置参数写法（8 个文件 23 处），而 `useToast().showToast` 接收 `{ type, message }`。
- 影响：运行时把字符串当 options 展开 → 弹出一条**无文案、无颜色**的空白提示条（成功/失败反馈全部丢失），且 `danger` 不是合法类型。
- 修复：23 处改为对象调用（`danger` → `error`）；后续 `useToast` 拆到独立模块后类型可直接校验。
- 复验：移动端创建企业后实测 toast 文案"企业创建成功"可见。

### P1-4 移动端输入框 onChange 签名错误（输入即抛错）

- 现象：`Input` 组件回调签名是 `(v: string) => void`，但 `ChangePasswordScreen`（3 处）与 `ProfileScreen`（1 处）写成 `(e) => setX(e.target.value)`。
- 影响：输入时 `e.target` 为 `undefined` → 抛 TypeError，受控值不更新 → **移动端修改密码/改姓名不可用**。
- 修复：改为 `onChange={setX}`。
- 复验：移动端 390 实测两个密码框输入后 `input_value()` 与输入一致。

### P1-5 空态按钮传参错误（按钮无文案/点击报错）

- 现象：8 处把 `EmptyState` 的 `action` 传成字符串 + `onAction`（`action="创建企业"`），组件实际要求 `action={{ label, onPress }}`。
- 影响：空态主按钮渲染为无文案按钮，`action.onPress` 为 `undefined`，点击无效（新建企业/新建预案/重试等引导入口失效）。
- 涉及：`EnterpriseListScreen`、`PlanCardsScreen`（2）、`ResourceListScreen`、`ResourceInvestigationScreen`、`RiskAssessmentScreen`、`DashboardScreen`、`EnterprisePlanListScreen`。

### P1-6 移动端预案编辑器本地草稿写入垃圾数据

- 现象：`addDraft(planId, sectionKey, content)` 位置参数调用，而 store 签名是 `addDraft({ planId, sectionKey, content, updatedAt })`。
- 影响：草稿条目字段全部 `undefined`，store 里出现无效草稿（"保存失败已暂存本地草稿"的恢复链路不可靠）。
- 修复：改为对象调用，补 `updatedAt: Date.now()`。

### P1-7 移动端企业详情"应急资源"永远为空

- 现象：`listResources()` 返回 `ApiResponse` 包装（`{code,message,data:{items}}`），页面却读 `resources?.items`；且列表项字段用了不存在的 `res.type`（应为 `res.category`）。
- 影响：详情页资源 Tab 恒显示"暂无应急资源"，统计口径误导。
- 修复：改读 `resources?.data?.items`，字段改 `res.category`。

### P2-1 antd v6 `Divider` 属性失效（权限分组标题不左对齐）

- 现象：`<Divider orientation="left">`——v6 的 `orientation` 只接受 `horizontal|vertical`，文本位置改用 `titlePlacement`。
- 修复：改 `titlePlacement="start"`（2 处）。

### P2-2 法规图谱力导布局随机 + 渲染期读 ref

- 现象：`RegulationGraph` 用 `Math.random()` 初始化节点位置，并把 `simNodes/simEdges` 存在 ref、在**渲染期读取**（同时还存在渲染期写 ref：`panRef.current = pan`）。
- 影响：每次数据/筛选变化都重新随机布局（视觉跳变）；ref 变化不触发重渲染，交互态（拖拽光标）不同步。
- 修复：哈希派生确定性初始位置；布局计算移入 `useMemo`（纯计算）；拖拽状态改用 state；新增 2 个 effect 同步 wheel 监听所需的 `pan/zoom` ref。

### P2-3 富文本"AI 重写"上下文可能过期

- 现象：`RichTextEditor` 在渲染期读 `editorRef.current.state.doc` 计算 `contextBefore/After`（ref 变化不触发重渲染）。
- 修复：上下文改由 `onSelectionUpdate` 写入 state，渲染期只读 state；`editorReady` 用 state 取代 ref 判断。

### P2-4 移动端 AI 生成弹窗风格参数未传递

- 现象：`onGenerate(selectedChapters)` 少传第二个参数 `styleParams`，同时 `DEFAULT_MOBILE_STYLE` 未被使用（死常量）。
- 修复：按选择映射 `detail_level` 后传递 `{...DEFAULT_MOBILE_STYLE, detail_level}`。

### P2-5 法规更新接口类型过严 / 风险等级 `as any`

- `updateRegulation(id, data: RegulationCreateRequest)` 让"只提交被编辑字段"的调用报错（靠 `@ts-nocheck` 掩盖）；后端实现是增量更新（`parsed.get(...)` 取默认值）→ 参数改为 `Partial<RegulationCreateRequest>`。
- `RiskSourceForm` 的风险等级渲染 `level={v as any}` → 收口为 `RiskLevel` 联合类型。

### P2-6 源码卫生：34 个前端源文件带 UTF-8 BOM

- 影响：BOM 会让补丁/工具按字节匹配失败（本轮 `Toast.tsx` 就因 BOM 导致补丁无法套用），历史事故同源。
- 修复：移除 34 个文件 BOM（逐字节保留其余内容，diff 为每文件 1 行）；新增 `frontend/scripts/check-source-hygiene.mjs` + CI 阻塞步骤 + `npm run check:hygiene`；补后端守护测试 `test_frontend_sources_have_no_bom`。

### P3-1 4 处乱码注释

- `PlanCardsScreen` 中 4 条注释为 GBK 误解码产物（如 `// 鏃犱紒涓?`），已按上下文还原为中文。

## 五、必须说明的工程折衷（3 处微任务排期）

`react-hooks/set-state-in-effect`（React Compiler 规则）会**穿透到 effect 里调用的组件内 `useCallback`**，即使函数体第一步就是 `await`：实测"内联 async IIFE / `.then` 回调"允许，"调用组件内 useCallback"报错。

因此有 3 处采用"把启动动作排到微任务"的写法，让 state 更新发生在 effect 同步阶段之外：

1. `ReportWorkspace`：`void Promise.resolve().then(() => loadDocument())`
2. `PlanEditorPage` 自动触发生成：`void Promise.resolve().then(() => startRealtimeGeneration(...))`
3. `WorkbenchCanvas` 工具切换清理：`void Promise.resolve().then(() => {...setters...})`（这些 setter 内部同时写 ref，渲染期调用会被 `refs` 规则判为读 ref）

**这不是行为等价之外的"藏问题"**：三处副作用与原先完全相同，只是延后一个微任务；若后续 React 编译规则收紧边界，这 3 处应优先重写为"事件处理器/状态机驱动"，而不是继续堆微任务。
