### N-5（P1 功能断链）作业票审批对"非企业主审批人"完全不可达，且没有"我的待办"

**取证**

- 前端 `WorkTicketApprovalPage.tsx` 注释自认遗留："后端也没有'我的待办'接口……按角色收窄待办需要后端补接口"；

**修复**

| 层 | 改动 | 关键点 |
| --- | --- | --- |
| 服务 | `access_control.ensure_enterprise_visible()` | 所有者 → `(企业, True)`；`enterprise_members` 里已绑定且 `enabled` 的成员 → `(企业, False)`；其余仍 404 |
| 服务 | `work_ticket_service.tickets_pending_for_user()` / `member_can_view_ticket()` | 按"当前节点可签人 × 是否已签"筛选；成员对自己签过的票仍可回看/打印 |
| 路由 | `GET /work-ticket/tickets` 新增 `assigned_to_me` | **成员在任何情况下都只返回与自己有关的票**（不传参也不放行全量）；企业主传 `true` 才是"轮到我签" |
| 路由 | 详情 / 打印 / `node-action` 改走 `_visible_ticket()` | 读与签字放宽到成员；**开票、提交、气体检测仍仅企业主**（不放宽写面） |
| 前端 | 审批工作台新增「只看我的待办」开关（默认开）+ 空态文案；删除过时遗留注释 | 关掉后企业主可看全部审批中票据 |

**证据**：`output/playwright/e2e-20260918/scripts/_work_ticket_member_todo_probe.py` → **21/21 PASS**
（临时提权建两个账号 → 建组织树 → 绑定审批成员 → 开票 → 气体检测 → 提交 → 成员待办命中 → 非成员 404 → 匿名 401 → 成员签字 → 待办清空但票仍可回看）。

### N-10（P3 日志噪音）passlib 每次登录都打一条 bcrypt 回溯

**取证**：后端日志里每次登录/改密都会出现
`(trapped) error reading bcrypt version` + `AttributeError: module 'bcrypt' has no attribute '__about__'`。
根因是 `passlib 1.7.4` 的后端自检读取 `bcrypt.__about__.__version__`，而 `bcrypt>=4.1` 已移除该属性；
passlib 会捕获它（功能正常），但 ERROR 级回溯会持续污染日志、掩盖真实错误。

**处置**：不改依赖版本（重建镜像会按 `>=x,<y` 范围拉到新版本，引入未验证的漂移），
改为在 `app/services/auth_service.py` 里补一个只读属性 shim，让 passlib 的自检回到预期路径；
**哈希算法与密文格式不变（仍是 `$2b$`）**。

**证据**：重启后执行真实登录 → `login=200`、近 30 秒日志里 `bcrypt version|__about__|AttributeError` 计数 **0**
（修复前每次登录必现）；容器内直接跑 `hash_password/verify_password` → `prefix=$2b$ verify=True wrong=False`；后端 75 条 auth 相关单测 + 全量 1921 条通过。

**当场抓到 2 个"内容被静默丢弃"的真缺陷**：

### N-13（P1 内容丢失）正文里提到章节名，整段被删 —— 导出的预案会"只剩标题"

**现象**：25 章全部填满的预案，导出后的 DOCX **只有封面、目录和章节标题，一条正文都没有**；
导出预览（HTML）同样空白。而只填 1–2 章时正文正常。

**定位过程**：二分复现 → 与章节数量无关，与**正文内容**有关：

| 章节名 | 正文 | 结果 |
| --- | --- | --- |
| 总则 | `<p>AAA 组正文段落。</p>` | 保留 |
| 总则 | `<p>正文包含总则二字</p>` | **被删** |
| 总则 | `<p>探针正文：总则。</p>` | **被删** |
| 总则 | `<p>总则概述</p>` | **被删** |

**根因**：预览与 DOCX 共用的 `app/services/plan_section_content.py::strip_section_heading`
用**子串包含**判断"这一行是不是重复的章节标题"（`section_title in text`），
于是任何 ≤80 字的开头段落只要提到章节名就被当作"重复标题"删掉；
循环还会连续删除多段。真实正文里"本节依据《安全生产法》编写""本章介绍应急组织机构及职责"
这类句子非常常见 → 导出内容静默缺失，且没有任何提示。

**修复**：改为**归一化等值**判定——去掉标签、编号前缀（`1.2`、`一、`、`第3章`、`（1）`）、
首尾标点后要求与章节名完全相等才剥离；未传章节名时保留旧的宽松行为（既有调用方契约）。
补 12 条参数化 + 4 条专项单测（`backend/tests/test_plan_section_heading_strip.py`）。

### N-14（P1 内容丢失）手工编辑的流程图在导出时被静默丢弃

**现象**：章节里内嵌 Mermaid 代码，但该章节没有预渲染 SVG 缓存时，导出的 DOCX 里**没有这张图**，
也没有任何提示（实测 `inline_shapes=0`）。

**根因**：`generate_plan_docx` 里把 `<code class="language-mermaid">` 的 hash 只记为"已见过"，
不生成渲染项；能用的 SVG 只有两个来源——内容里的内联 `<div class="mermaid-rendered">`
或 `PlanSection.mermaid_svgs` 缓存。生成期预渲染只覆盖 AI 产出的内容，
用户手工编辑/粘贴的 mermaid 块两边都不占 → 被丢弃。

**修复**：新增纯函数 `missing_mermaid_codes(codes, mermaid_svgs, covered_hashes)`
并在导出循环里对未覆盖的代码**就地渲染**（mermaid.js + Playwright 的渲染能力此前已具备，
只是没被调用）；渲染失败仍是"不阻断导出"。
（自审：第一版兜底我误把"见过 hash"的集合当成"已覆盖"传进去，导致兜底永不触发——
 已用 `covered_hashes` 修正，并补一条调用点守护测试。）

### N-16（P1 功能断点）作业票批准之后没有任何出口：不能开始作业 / 完工 / 归档

**取证**：

- 状态机 `work_ticket_flow.TRANSITIONS` 定义了 `approved →working →finished →closed`
  （还有 `cancel`/`expire`），前端类型里也早就写好"作业中/已完工/已归档"的中文标签；
- 但后端路由**只有 8 个端点**（模板/列表/开票/气体检测/提交/审批/详情/打印），
  没有任何端点能触发 start/finish/close；前端详情页也只有「提交审批」和「打印票面」两个按钮。
- 结果：票批准后永远停在"已批准"，**完工与归档留痕无从产生**——而 GB 30871-2022 要求作业票至少保存一年，
  归档动作本身就是要留痕的事实。

**修复**：

| 层 | 改动 |
| --- | --- |
| 状态机 | `work_ticket_flow` 增 `LIFECYCLE_ACTIONS`（start→working / finish→finished / close→closed / cancel→cancelled）与 `lifecycle_target()`，与 `TRANSITIONS`（能不能做）配套 |
| 服务 | `transition_ticket()`：状态机校验、**超期保护**（批准后已过 `valid_to` → 置 `expired` 并留痕后拒绝开工）、每步写 `work_ticket_audit_logs`、完工/归档时清空当前审批节点指针 |
| 路由 | 新端点 `POST /work-ticket/tickets/{id}/transition`（仅企业主；审批节点动作仍走 `/node-action`，两者语义分开） |
| 详情接口 | 新增 `audit_logs`（全量流转留痕：开票/提交/审批/开始作业/完工/归档/作废/过期） |
| 前端 | 详情页按状态给出「开始作业 / 完工 / 归档」主按钮 + 「作废」（二次确认）；时间线改为渲染全量流转留痕（带 状态→状态、办理人、时间） |

**证据**：

- `_work_ticket_member_todo_probe.py` → **29/29 PASS**：成员审批通过后，企业主 `start→working`、`finish→finished`、
  `close→closed`，已归档再作废返回 **409**，`audit_logs` 覆盖 `open/submit/approve/start/finish/close`；
- `_work_ticket_lifecycle_ui_probe.py` → **4/4 PASS**：draft / approved / working / finished 四种状态下
  页面只出现该状态应有的动作按钮（在 8082 产物上复跑通过）；

## 一之补二：批量导入专项（又抓到 3 处真缺陷，其中资源导入整体不可用）

同样的"扫一个功能族"思路用到**Excel 批量导入**（HR/安全员一次导几十上百行，坏了影响面很大），
写了成员导入与资源导入两个端到端探针，结果抓到 3 个真缺陷：

### N-17（P1 路由遮蔽）资源导入模板下载被参数化路由抢先匹配 → 422

**现象**：`GET /enterprises/{id}/resources/template` 返回 422「请求参数无效（如 ID 格式错误…）」。

**根因**：`enterprise_sub.router` 在 `resources_ext.router` **之前**注册，而它的详情路由写成
`/{enterprise_id}/resources/{resource_id}`（无类型约束）——"template" 被当成 `resource_id`
匹配进去，UUID 转换失败 → 422。前端「第一步：下载模板」因此必失败，资源导入实际上手都上不了。

**修复**：三条详情路由约束为 `{resource_id:uuid}`、参数类型改 `uuid.UUID`（查询显式 `str()`）；
补 `test_route_shadowing_guard.py`（守护"字面量路径不得被无约束参数路径吞掉"）。

### N-18（P1 功能整体不可用）资源导入上传必 500

**现象**：修好模板下载后，上传任何 xlsx 都返回 500。

**根因**：`wb = Workbook(io.BytesIO(contents))` —— openpyxl 的 `Workbook()` 第一个参数是
`write_only`，传入 BytesIO 只会**新建一个空白只写工作簿**、完全忽略上传内容，
于是 `wb.active` 为 None → `AttributeError: 'NoneType' object has no attribute 'iter_rows'`。
同一误用还有第二处（`risk_sources_ext.py` 的风险源导入）。

**修复**：两处都改为 `load_workbook(io.BytesIO(contents), data_only=True)`，并对损坏文件返回
**400「导入文件格式无效，请使用模板」**（不再 500）；补 `test_excel_import_workbook_usage.py`
（扫全部 router，禁止 `Workbook(BytesIO)` 写法 + 要求 400 兜底存在）。

### N-19（P2 数据质量）模板自带的示例行会被整批导进真实台账

**取证**：下载的模板第 2 行是示例数据（干粉灭火器 / 张三 / 13800001111），
而前端确认步骤是 `validItems = previewItems.filter(errors.length === 0)`（**没有逐行勾选**）
→ 用户只要不手动删掉示例行，它就会被当成真实资源写进台账。

## 一之补四：四色图工作台 + 聊天助手工具链（各自抓到问题）

### N-23（P1 助手工具层）一个坏工具会毒化整轮对话，且 `list_templates` 必然失败

**方法**：聊天助手的 37 个工具由模型按需调用，出问题时只表现为"助手答不出来"。
本轮写了 `backend/scripts/check_chat_tools.py`：**绕过 LLM 直接 `dispatch()` 每个工具**
（零额度），把"工具层"与"模型层"分开验证。

**结果（修复前 8/18）**：`list_templates` 报
`'PlanTemplate' object has no attribute 'description'`（模型上根本没有该列，该工具 100% 失败）；
**紧随其后**的 9 个关系型工具（`list_plans`/`get_enterprise`/`get_plan`/`list_resources`/
`list_risk_sources`/`list_resource_investigations`/`list_risk_assessments`/
`get_generation_progress`/`query_enterprise_knowledge`）统统一致地报
`greenlet_spawn has not been called; can't call await_only() here`。

**根因（两个）**：

1. `_list_templates` 读取不存在的 `t.description`；
2. `dispatch()` 的兜底是"任何异常都 `await db.rollback()`"——普通 Python 异常本不需要回滚，

   `MissingGreenlet`。**一个坏工具把同一轮里其它工具全带崩**，且报错信息完全误导
   （像是并发/事件循环问题，实际是工具 bug + 恢复策略不当）。

**修复**：`_list_templates` 只返回真实列（`id/name/plan_type/version/section_count`）；
`dispatch()` 仅对 `SQLAlchemyError` 回滚，并在回滚后 `expunge_all()` 清 identity map，
避免后续工具拿到过期对象。

**复验**：`check_chat_tools.py` → **18/18 PASS**（含修复前失败的 10 个）；

## 一之补五：外部对接、版本回滚（各抓到一处真缺陷）

### N-25（P1 路由遮蔽，第三次）预案「版本对比」整体不可用

**取证**：`GET /plans/{id}/versions/compare?a=2&b=3` 返回 **422**（"请求参数无效"）。
原因是 `versions.py` 里字面量路由 `/versions/compare` 声明在参数路由 `/versions/{version_id}`
**之后**，`compare` 被当成版本 id 去查库 → Postgres UUID 转换失败 → 应用中间件把 DB 错误统一转成 422。
也就是说，**版本对比功能在页面上点一次就会报错**（探针实测：修复前 compare 恒 422）。

**修复**：①把 `/versions/compare` 路由前移到参数路由之前；②给详情路由加 `{version_id:uuid}` 约束
（同一个坑已是第三次出现——每一次都是"字面量路径被无约束参数路径吞掉"，因此这次连防御性约束一起加），
③守护测试断言"compare 在参数路由之前"且"参数路由必须 `:uuid`"。

**复验**：`_plan_versions_probe.py` → **11/11 PASS**：存 V1/V2 快照 → 列表倒序 `[3,2]` →
**对比识别出 `sec_1: modified`（V1→V2 内容）** → 回滚到 V1 后**章节内容真的变回 V1**、
`current_version=2`、快照历史未被删改；探针预案删除后版本残留 0。

### N-26（P2 外部对接幂等）外部下单接口重复调用会重复开单 + 重复烧 AI

**取证**：`POST /api/external/plans` 每次调用都新建 `PlanProject` 并 `spawn` 一次生成任务；

**证据**：`backend/tests/test_external_idempotency.py` 3 例（重复订单不再进创建分支且不 spawn、

> 幂等分支已由单测覆盖，中间件边界由探针覆盖。

## 二、设计取舍（为什么这样修）

1. **成员只放宽"读 + 签字"**：开票、提交、气体检测仍要求企业主。会签要的是"审批人进来签字"，
   不是把写权限摊开；越权面保持最小。
2. **失败仍返回 404 而不是 403**：沿用项目既有约定（不用状态码探测资源是否存在）。
3. **AI 清单补全保持"人工勾选"两段式**：不在任务生成期自动调 LLM——每次生成都付一次调用成本与延迟，
   且 AI 静默改写清单会让"谁加的这条"说不清。落库端点负责去重与状态回退，前端只做勾选。
4. **批次风格覆盖缺省回落**：`style_override or p.style_preference`，既有 Web 调用方无需改动。
