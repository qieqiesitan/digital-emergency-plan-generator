## 一、本轮发现与处置

### N-5（P1 功能断链）作业票审批对"非企业主审批人"完全不可达，且没有"我的待办"

**取证**

- 前端 `WorkTicketApprovalPage.tsx` 注释自认遗留："后端也没有'我的待办'接口……按角色收窄待办需要后端补接口"；
- 运行时复核：`ensure_enterprise_owned` 只认 `Enterprise.user_id == 当前用户`，**绑定为审批成员的账号连列表都是 404**；
- 数据复核：`enterprise_members` 中 `user_id` 非空的绑定数为 **0** → GB 30871 的多单位会签在任何真实账号上都跑不起来（审批人进不去，能进的只有企业主一人）。

**修复**

| 层 | 改动 | 关键点 |
| --- | --- | --- |
| 服务 | `access_control.ensure_enterprise_visible()` | 所有者 → `(企业, True)`；`enterprise_members` 里已绑定且 `enabled` 的成员 → `(企业, False)`；其余仍 404 |
| 服务 | `work_ticket_service.tickets_pending_for_user()` / `member_can_view_ticket()` | 按"当前节点可签人 × 是否已签"筛选；成员对自己签过的票仍可回看/打印 |
| 路由 | `GET /work-ticket/tickets` 新增 `assigned_to_me` | **成员在任何情况下都只返回与自己有关的票**（不传参也不放行全量）；企业主传 `true` 才是"轮到我签" |
| 路由 | 详情 / 打印 / `node-action` 改走 `_visible_ticket()` | 读与签字放宽到成员；**开票、提交、气体检测仍仅企业主**（不放宽写面） |
| 前端 | 审批工作台新增「只看我的待办」开关（默认开）+ 空态文案；删除过时遗留注释 | 关掉后企业主可看全部审批中票据 |

**证据**：`output/playwright/e2e-20260918/scripts/_work_ticket_member_todo_probe.py` → **21/21 PASS**
（临时提权建两个账号 → 建组织树 → 绑定审批成员 → 开票 → 气体检测 → 提交 → 成员待办命中 → 非成员 404 → 匿名 401 → 成员签字 → 待办清空但票仍可回看）。
探针自带清理：临时用户 / 成员绑定 / 组织树 / 探针票据全部归零，QA 角色还原为 `user`。

### N-6（P1 功能断链）"AI 清单补全"只有半条链路

**取证**：`POST /hazard-inspection/ai/checklist` 端点存在、前端 `aiChecklistSuggestion()` service 也存在，
但**没有任何页面调用它**；后端也没有"把勾选的建议项写进任务"的端点。
服务端 docstring 写着"页面勾选后与既有清单项合并去重"——那一跳从来没实现，
`hazard_service.py` 里对应位置还留着一句 `TODO(task 12)`。

**修复**

| 层 | 改动 |
| --- | --- |
| 后端（新端点） | `POST /hazard-inspection/tasks/{task_id}/items`：按 `content` 去重、单次 ≤20 条、纯空白内容 422；权限 = 任务责任人 / 企业主 / 企业管理员（其余 403，非成员仍 404） |
| 后端（状态一致性） | 已 `done` 的任务被追加 pending 项时回退为 `processing` 并清 `completed_at`——消除"已完成但清单里还有未核对项"的自相矛盾 |
| 前端 | 任务执行弹窗新增「AI 补全清单」→ 建议勾选弹窗 → 「加入清单」；重复项提示"已全部跳过" |
| 文档性修正 | 清掉 `hazard_service.py` 里已过期的 TODO，写明"建议 → 勾选 → 落库"两段式是**刻意设计**（生成任务时不自动调 LLM：避免成本/延迟，也不让 AI 静默改写清单） |

**证据**：`_hazard_ai_checklist_probe.py` → **8/8 PASS**（真实浏览器点按钮 → 弹窗展示建议 → 落库成功提示 → 复查清单含新项且重复项只出现 1 次）。
AI 响应用 route 拦截伪造，**零 LLM 费用**；后端新增 6 条单测（去重、状态回退、责任人/管理员/非成员三种权限、空白 422、跨企业 404）。

### N-7（P2 功能不一致）移动端批量生成"选了风格也不生效"

**取证**：`generate_batch_background` 只读预案保存的 `p.style_preference`，
移动端为此**直接隐藏**了批量模式下的风格选择（组件注释自认）——用户看不到选择，也谈不上生效。

**修复**：两个 batch 端点（SSE 与 background）接受请求级 `style_preference` / `advanced_prompt_overrides`
（非 dict 一律忽略，缺省回落到预案风格，既有调用方零改动）；解析逻辑抽成 `_parse_batch_request()` 便于单测；
前端 service / 类型透传；移动端批量模式恢复风格选择。

**证据**：`_v6_ui_probe.py` → **11/11 PASS**，其中真实浏览器捕获到的批量请求体里
`style_preference.detail_level == "concise"`（此前该字段根本不会出现在请求里）。

## 二、设计取舍（为什么这样修）

1. **成员只放宽"读 + 签字"**：开票、提交、气体检测仍要求企业主。会签要的是"审批人进来签字"，
   不是把写权限摊开；越权面保持最小。
2. **失败仍返回 404 而不是 403**：沿用项目既有约定（不用状态码探测资源是否存在）。
3. **AI 清单补全保持"人工勾选"两段式**：不在任务生成期自动调 LLM——每次生成都付一次调用成本与延迟，
   且 AI 静默改写清单会让"谁加的这条"说不清。落库端点负责去重与状态回退，前端只做勾选。
4. **批次风格覆盖缺省回落**：`style_override or p.style_preference`，既有 Web 调用方无需改动。
