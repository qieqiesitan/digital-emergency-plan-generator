# 系统可配置化管理 — 完整实施方案 v2（中台深度整合）

> 制定日期：2026-06-16  
> 核心策略：管理类跳中台UI（零开发），业务类调中台API自建UI，中台没有的全自建

---

## 一、总体策略

```
管理类（纯CRUD） → 跳中台UI，只加链接入口
业务类（预案专属）→ 调用中台API + 自建UI
中台没有的        → 全部自建（表+API+UI）
```

## 二、复用清单（跳中台，零开发）

| 模块 | 中台路径 | 前端操作 |
|------|---------|---------|
| 字典管理 | `/system/dict` 页面 | MainLayout 新增「系统管理→字典管理」菜单项，点击跳中台 |
| 菜单管理 | `/system/menu` 页面 | MainLayout 新增「系统管理→菜单管理」菜单项，点击跳中台 |
| AI供应商管理 | `/ai/provider` 页面 | MainLayout 新增「AI管理→供应商管理」菜单项，点击跳中台 |
| AI模型管理 | `/ai/model` 页面 | MainLayout 新增「AI管理→模型管理」菜单项，点击跳中台 |

中台跳转方式：qiankun 路由切换 或 `window.open` 新窗口（复用现有 qiankun 集成基础）。

## 三、自建清单

### 模块一：AI提示词管理

**核心价值**：预案生成质量由提示词决定，需要预案系统专属的管理界面，但底层存储复用中台 `ai_prompt_template` 表。

**中台已有能力**：
- `ai_prompt_template` 表：`system_prompt`, `user_prompt_template`, `variables`(JSONB), `category`, `temperature`, `max_tokens`, `model_id`
- `/ai/prompt` API：完整 CRUD + 单条测试 + 批量测试
- 变量替换：`{{变量名}}` 语法，自动渲染
- 已有 Vue 管理界面（通用版）

**预案系统自建内容**：

后端（Python 代理层）：
- `app/routers/prompts.py` — 代理路由，转发到中台 `/ai/prompt`
  - `GET /api/v1/prompts?category=emergency_*` — 按预案类型+章节筛选
  - `GET /api/v1/prompts/:id` — 单个模板
  - `POST /api/v1/prompts` — 创建（自动设置 category 前缀）
  - `PUT /api/v1/prompts/:id` — 更新
  - `POST /api/v1/prompts/:id/test` — 用示例数据测试
- `app/ywt_client.py` 新增 `call_prompt_api()` 方法

前端：
- `pages/Settings/PromptManagePage.tsx` — 预案专属提示词管理
  - 顶部按预案类型切换Tab（综合应急预案 / 专项应急预案 / 现场处置方案）
  - 左侧：提示词类型树（系统提示词 / 章节提示词 / Mermaid流程图 / 周边环境调查）
  - 右侧：编辑区（系统提示词 + 用户提示词模板）
  - 变量面板：列出可用变量（如 `{enterprise_data}` `{section_title}` `{section_number}`）
  - 「预览渲染」按钮：用模拟数据展示渲染后效果
  - 「在线测试」按钮：调用真实LLM验证效果
- `services/promptService.ts` — 提示词 API 封装

核心代码改造：
```python
# generation.py 改造前（当前）
def _build_system_prompt() -> str:
    return """你是一位持有国家注册安全工程师资格的..."""  # ~100行硬编码

# generation.py 改造后
async def _build_system_prompt(db, plan_type: str) -> str:
    prompt = await ywt_client.get_prompt(category=f"emergency_system", plan_type=plan_type)
    return prompt["system_prompt"]
```

改造范围：
- `generation.py`：`_build_system_prompt()`, `_build_section_prompt()`, `_get_mermaid_instruction()` → 改从API加载
- `surrounding_ai.py`：全部系统/用户提示词 → 改从API加载
- 增加内存缓存（TTL 5分钟），避免每次生成都请求中台

数据迁移脚本：
1. `_build_system_prompt()` 全文 → `ai_prompt_template`（category=`emergency_system`，plan_type=`*`）
2. `_chapter_data.json` 5个章节 → category=`emergency_section`，section_key 对应
3. `surrounding_ai.py` 提示词 → category=`emergency_surrounding_system` / `emergency_surrounding_user`
4. `_get_mermaid_instruction()` → category=`emergency_mermaid`
5. `FLOWCHART_SECTION_MAP` → 存入字典表，dict_type=`emergency_flowchart_sections`

### 模块二：字典动态加载

**核心价值**：前端下拉框选项从硬编码改为中台字典API动态加载，新增选项不用改代码。

**中台已有能力**：
- `sys_dict_type` + `sys_dict_data` 表
- `/system/dict/data/type/{dictType}` — 按类型获取启用的字典条目（按 sort 排序）

**预案系统自建内容**：

后端：
- `app/routers/dict.py` — 代理路由
  - `GET /api/v1/dicts/{dict_type}` → 调中台 `/system/dict/data/type/{dict_type}`
  - Redis/内存缓存（TTL 30分钟）

前端：
- `hooks/useDict.ts` — 字典加载 Hook
  ```tsx
  const { items, loading } = useDict('risk_categories');
  // 替换原来: import { PRESET_RISK_CATEGORIES } from '@/utils/constants';
  ```
- 改造 `utils/constants.ts`：删除所有 `PRESET_*` 硬编码常量
- 改造所有使用这些常量的下拉框组件

需要在中台创建的字典类型（迁移数据）：

| dict_type | 说明 | 数据来源 |
|-----------|------|---------|
| `risk_categories` | 风险类别 | 原 `PRESET_RISK_CATEGORIES` |
| `emergency_groups` | 应急小组 | 原 `PRESET_EMERGENCY_GROUPS` |
| `internal_resource_categories` | 内部应急资源类别 | 原 `PRESET_INTERNAL_RESOURCE_CATEGORIES` |
| `external_resource_categories` | 外部应急资源类别 | 原 `PRESET_EXTERNAL_RESOURCE_CATEGORIES` |
| `industries` | 行业类别 | 原 `PRESET_INDUSTRIES` |
| `plan_types` | 预案类型 | 原 `PLAN_TYPE_LABELS` |
| `plan_statuses` | 预案状态 | 原 `PLAN_STATUS_LABELS` |
| `emergency_flowchart_sections` | 需生成流程图的章节 | 原 `FLOWCHART_SECTION_MAP` |
| `ai_provider_urls` | AI供应商默认URL | 原 ai_config.py 硬编码映射 |
| `surrounding_directions` | 周边环境方向枚举 | 原 `DIRECTIONS = ["N","NE",...]` |

### 模块三：系统配置 + 领域参数

**核心价值**：中台没有 `sys_config` 表，需要自建；风险矩阵、响应分级等应急预案专属参数也在这里管理。

**自建内容**：

数据库（预案系统自己的 PostgreSQL）：
```sql
CREATE TABLE sys_config (
    id           BIGSERIAL PRIMARY KEY,
    config_key   VARCHAR(128) NOT NULL UNIQUE,
    config_value TEXT NOT NULL,
    config_type  VARCHAR(16) DEFAULT 'string',   -- string / int / float / bool / json
    description  VARCHAR(512),
    created_at   TIMESTAMP DEFAULT now(),
    updated_at   TIMESTAMP DEFAULT now()
);
```

配置项规划：

| config_key | config_type | 说明 | 当前来源 |
|-----------|------------|------|---------|
| `risk_matrix_l_scale` | json | L量表5级描述 | `_chapter_data.json` ch3 |
| `risk_matrix_s_scale` | json | S量表5级描述 | `_chapter_data.json` ch3 |
| `response_level_iii_def` | string | Ⅲ级响应定义 | `_build_system_prompt()` 内嵌 |
| `response_level_ii_def` | string | Ⅱ级响应定义 | `_build_system_prompt()` 内嵌 |
| `response_level_i_def` | string | Ⅰ级响应定义 | `_build_system_prompt()` 内嵌 |
| `export_dir` | string | 导出文件目录 | `config.py` settings |
| `prompt_cache_ttl` | int | 提示词缓存时间(秒) | 新增，默认300 |

后端：
- `app/routers/config.py` — CRUD API（`GET/PUT /api/v1/configs`）
- `app/dependencies.py` 增加 `async def get_config(key: str) -> str`（内存缓存）

前端：
- `pages/Settings/SystemConfigPage.tsx` — 系统配置管理表格

代码改造：
- `config.py`：`EXPORT_DIR` 等从 `sys_config` 覆盖
- `generation.py`：风险矩阵参数从 `sys_config` 读取注入提示词

## 七、关键假设与风险

| 假设 | 风险 | 应对 |
|------|------|------|
| 中台API始终可用 | 中台挂了预案系统也无法生成 | 代理层加 TTL 缓存 + fallback 默认值 |
| 中台 `category` 字段作为预案分类键 | 和其他系统冲突 | 统一使用 `emergency_` 前缀隔离 |
| 中台字典无需 `sysCode` 隔离 | 多租户时可能混淆 | 如果将来多租户，创建时设置 `sysCode='emergency-plan'` |
| qiankun 路由切换可跳中台管理页 | qiankun 模式下路由受限 | 备选方案：`window.open` 新窗口 |
| 中台 Prompt 模板 `variables` 格式兼容 | `{{}}` vs `${}` 语法差异 | 中台用 `{{变量}}`，预案系统目前无模板引擎，保持一致 |

## 八、优劣势分析

**优势**：
- 字典/菜单/供应商/模型 四个模块零开发，直接复用中台成熟UI
- 提示词复用中台 `ai_prompt_template` 表结构和测试能力，不重复造轮子
- 总工作量从纯自建 7-10天 压缩到 8天（去掉了一个数据库设计+CRUD的重复劳动）
- 中台迭代升级（如提示词版本管理），预案系统自动受益
- 管理入口统一，用户在中台和预案系统间无缝切换

**劣势/风险**：
- 依赖中台必须运行（预案系统启动前需确保中台可用）
- 中台API变更可能导致预案系统代理层需同步更新
- 提示词管理UI虽自建但底层表结构受中台约束（如需要预案专属字段需走中台变更流程）
- 跳中台的页面与预案系统视觉风格可能不完全一致（qiankun 模式下可控）
