# 移动端完成度评估（2026-09-20）

> 评估对象：`frontend/src/mobile/`（`/m/*` 路由 + `m.html` 入口 + 8082 PWA 站点）
> 评估方式：**只读**。源码盘点 + 真浏览器实测（390×844 iPhone UA，真账号登录，跑 8082 生产构建）
> 本轮未改任何业务代码，未写库。

---

## 一、结论

**你的感觉是对的：移动端目前是一个"能登录、能编预案"的骨架，不是能下现场干活的移动工作台。**

量化口径（同一仓库实测）：

| 口径 | 桌面端 | 移动端 | 覆盖率 |
| --- | --- | --- | --- |
| 业务路由条目 | 67（含模块子路由） | 19 | **28%** |
| 一级功能模块 | 12 + 6 张公开页 | 5（其中 2 个残缺） | **约 30%** |
| 前端代码量（pages/components vs mobile） | 37,855 行 | 6,882 行 | **18%** |

按"场景覆盖"加权（现场手机最该干的事：隐患上报、风险/隐患巡查、离线记录、看预案章节、AI 问答）：
**已完成约 35%，缺口集中在"现场执行类"模块**——隐患排查治理、重大危险源、特殊作业票、应急组织、
周边环境/危化品台账在移动端**一页都没有**。

最严重的一条不是"少页面"，而是：**扫码上报/公示这类"专为手机设计的公开链接，在手机上打不开"**（见 P0-1）。

## 三、问题清单（按优先级，均带实测证据）

### P0-1 公开链接（扫码上报 / 公示）在手机上全部打不开，落到登录页

**实测对照**（同一 URL，同一构建，仅 UA 不同；脚本 `_mobile_public_link_probe.py`）：

| URL | 桌面 UA | iPhone UA |
| --- | --- | --- |
| `/h/report/FAKE_TOKEN`（扫码上报） | `免登录公开上报` 表单正常渲染 | → **`/m/login`** |
| `/h/FAKE_TOKEN`（隐患公示） | `链接已失效` | → **`/m/login`** |
| `/r/FAKE_TOKEN`（告知卡） | `卡片不存在或链接已失效` | → **`/m/login`** |
| `/p/risk/FAKE_TOKEN`（风险公示） | `链接已失效` | → **`/m/login`** |

**根因**：入口分发按 UA/宽度走移动端分支，而移动端路由表里没有这 4 条公开路由。

```
frontend/src/entry.tsx:16   if (isMobilePath() || isMobile())  → MobileApp
frontend/src/main.tsx:12    同上
frontend/src/mobile/utils/platform.ts:5   isMobile() = UA(Mobi/iPhone/…) || innerWidth <= 768
frontend/src/mobile/routes.tsx:70         { path: "*", element: <Navigate to="/m/dashboard" /> }
                                          + AuthGuard → 未登录直接 /m/login
```

**为什么是 P0**：隐患扫码上报/公示的产品前提就是"工人拿手机扫"。现在这条路在手机上 100% 走不通，
而且跳转到登录页（连"该页面请在电脑端打开"都没有），用户只会认为链接坏了。

### P1-1 桌面专有深链在手机上"静默回工作台"，没有任何提示

16/16 条桌面深链在 iPhone UA 下全部落到 `/m/dashboard`（脚本 `_mobile_coverage_probe.py`）：
`/enterprises/{id}/hazard`、`/hazard/dashboard`、`/major-hazard`、`/work-ticket`、`/org`、`/emergency-org`、
`/risk-management/workbench`、`/risk-management/notice-cards`、`/risk-management/methods`、
`/settings/users`、`/settings/regulations`、`/settings/data-hub`、`/settings/prompts`、`/onboarding`、
`/platform/overview`、`/chat`。

用户在手机上（或从别人发的链接进来）看到的是"莫名其妙回到工作台"。建议兜底页改为
"该功能请在电脑端使用 / 返回工作台"，而不是 `Navigate replace`。
`frontend/src/mobile/routes.tsx:70`

### P1-2 风险分级管控在移动端只读，且完成度卡片列的待补项没有对应页面

- `frontend/src/mobile/screens/RiskManagementListScreen.tsx:32` 空态原文：
  `请先在 Web 端维护风险分级管控数据`（实测截图 `m-risk-management.png` 同文案）。
- 工作台完成度卡片把 **应急组织 / 风险与危化品 / 周边环境 / 报告** 作为"待补数据"芯片列出，
  但 `handleCompletionAction` 只会跳企业详情（`DashboardScreen.tsx:159`），
  而企业详情只有 基本信息/风险管控/应急资源/调查报告 4 个 Tab（`EnterpriseDetailScreen.tsx:26`）。
  → 移动端点"去补数据"是个**会走进死胡同的入口**。

---

### P1-3 "离线编辑会在联网后同步"是空头承诺

- UI 承诺：`frontend/src/mobile/components/ui/NetworkStatusBanner.tsx:14`
  `离线模式 · 编辑内容将在恢复网络后同步`。
- 实际：`frontend/src/mobile/store/draftStore.ts` 用裸 `create()`（**无 persist**，无 localStorage/IndexedDB），
  `getPendingSyncDrafts()` / `markSynced()` **全仓库 0 调用者**，也**不存在** `useOfflineSync` hook
  （`frontend/src/mobile/hooks/` 只有 `useNetworkStatus.ts` 一个文件，开发计划里写的 6 个 hook 只落地了 1 个）。
  → 断网时编辑失败写入的草稿，**刷新页面即丢**，且永远不会被上传。

---

### P1-4 移动端零单测；唯一的 e2e 断言恒真

- `frontend/src/mobile/` 下**没有任何 `*.test.tsx`**（全仓 vitest 300 例里移动端 0 例）。
- `frontend/e2e/mobile-routing.spec.ts:15` 断言 `html.includes("数字化应急预案")` ——
  该字符串在桌面端页面同样存在，**这条用例无论移动端是否渲染都会通过**（假阳性）。
- 后果：本轮发现的 P0-1、P1-3 这类问题，现有门禁一条都拦不住。

## 四、与 `docs/移动端开发计划.md` 的对照（计划 vs 落地）

计划文档（v1.0，22 页/77 文件/8 周）里 4 个阶段的复选框**全部勾选**，但按代码核对：

| 计划要求 | 落地情况 |
| --- | --- |
| 19 个基础 UI 组件 | ✅ 22 个组件文件，齐全 |
| 6 个 hooks（键盘/网络/离线同步/生物识别/流式…） | ❌ 只有 `useNetworkStatus.ts` |
| 生物识别登录、LoginForm/RegisterForm/BiometricButton 独立组件 | ❌ 无（表单内联在 Screen 里） |
| 离线草稿 IndexedDB + 冲突解决 Dialog + 自动同步 | ❌ 只有内存 `draftStore`，无同步 |
| PWA 图标/离线指示 | ✅ 图标 192/512 真实尺寸，SW 已生成 |
| AI 流式生成（SSE + useStreamGeneration） | ⚠ 改成了"后台任务 + 轮询"（设计变更，已在 TASKS.md 记录） |
| 触觉反馈 `utils/haptics.ts` | ❌ 无 |
| 性能：移动端 JS < 300KB gzip | ❌ `mobile-vendor 34.9KB + mobile-ui 42.7KB + MobileApp 8.7KB`，另 preload 了桌面 477KB chunk |
| 设计审计 8 条铁律 | 未复核（本轮未做视觉审计） |

另外，计划本身**只覆盖到"企业 + 预案 + 设置"三条线**，从未包含隐患排查、重大危险源、
作业票、应急组织、法规库、数据中台——所以"移动端完成度低"一半是**计划范围就没有**，
一半是**计划范围内的离线/hook/测试也没做完**。

## 五、建议路线（按性价比排序）

**P0（先修，改动小、影响大）**
1. 公开页（`/r/:token`、`/p/risk/:token`、`/h/:token`、`/h/report/:token`）在移动端分支里放行：
   入口分发时先判断这批前缀直接走桌面 router，或在移动端 router 里直接挂这 4 条路由（免登录）。
2. 移动端兜底路由改成"功能提示页"，不要再静默 `Navigate` 到工作台。

**P1（把"承诺"变成事实）**
3. `draftStore` 加 persist（localStorage）+ 写 `useOfflineSync`：恢复网络后 PUT 章节并把
   `markSynced` 接上；在同步完成前，横幅文案降级为"离线，内容仅本机暂存"。
4. 补移动端单测（先覆盖 3 个高风险 Screen：编辑器草稿、导出轮询、登录跳转），
   修 `mobile-routing.spec.ts` 的恒真断言（改成断言移动端特有元素，如 TabBar 四项文字）。
5. 完成度卡片的待补项改为**只在移动端有页面的模块**可点（风险/资源/报告），其余标注"需在电脑端补录"。

**P2（补齐现场场景，需排期）**
6. 隐患排查治理移动端最小闭环：今日任务列表 + 扫码上报入口 + 隐患登记（后端 API 已具备：
   `POST /records`、`/ai/record-assist`、`/public/hazard/report/{token}`），约 3~5 人日。
7. 风险分级管控移动端"看 + 拍照留痕"（不做全量编辑器）：风险点列表/详情/管控措施/告知卡。
8. 重大危险源、作业票：先只做"查看 + 审批"，不做录入。

## 七、功能面量化（补测：端点级 + service 函数级）

| 前端 service 导出函数（36 个模块） | 346 | 47 | **13.6%**（桌面端 298 = 86%） |
| 前端页面/组件 | 页面 75 + 业务组件 79 | Screen 22 + 组件 28 | 约 32% |

### 7.3 结论

**不是"少几个页面"，而是"一半以上的后端能力在移动端没有入口"**，且已有入口的模块大多停在
"看列表 / 看报告"这一档：能读不能改（风险分级管控）、能建不能改（应急资源、企业部分字段）、
能生成不能复核（报告与预案都缺"生成并复核"门控）。
