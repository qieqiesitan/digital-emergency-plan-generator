## 1. 项目概况

### 1.1 开发目标

在现有桌面端 React SPA 工程内，新增移动端完整前端应用（PWA），复用全部后端 API，不修改任何后端代码。

### 1.2 技术路线

- 与桌面端共用 `frontend/` 工程，移动端代码集中在 `frontend/src/mobile/`
- 构建时通过 Vite `manualChunks` 将移动端 Bundle 与桌面端分离
- 根据 `navigator.userAgent` + `window.innerWidth ≤ 768` 自动分发移动端/桌面端入口
- 全部组件自研（不依赖 Ant Design Mobile/MUI/其他第三方 UI 库）

### 1.3 文件统计

|------|-----------|-----------|

## 2. 开发环境准备

> **前置条件**：确保桌面端 Docker 环境正常运行（`docker compose up -d`），后端 API 可通过 `http://localhost:8000` 访问。

### 2.1 依赖安装

```bash
cd frontend
npm install framer-motion idb-keyval zustand vite-plugin-pwa
npm install -D @types/react @types/react-dom
```

已有依赖（无需重装）：`react`、`react-dom`、`react-router-dom`、`@tanstack/react-query`、`axios`、`lucide-react`、`@tiptap/react`、`@tiptap/starter-kit`、`tailwindcss`、`typescript`

## 9. 风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| TipTap 移动端触摸兼容性差 | 中 | 高 | 备选：基于 `contentEditable` 自研简化编辑器，仅支持 加粗/斜体/标题/列表 |
| SSE 流式在 iOS Safari 不稳定 | 中 | 中 | 降级方案：轮询模式（3s 间隔 GET 章节内容） |
| IndexedDB 在微信浏览器中不可用 | 低 | 中 | 降级：仅使用内存草稿（页面不刷新不丢失） |
| PWA 在 iOS Safari 支持有限 | 高 | 低 | 不影响核心体验；PWA 安装为增强功能，浏览器访问为主 |
| `backdrop-filter` 在旧设备性能差 | 低 | 低 | TabBar 降级为纯色背景 `rgba(255,255,255,0.95)` |
| 企业切换器 N+1 查询性能 | 中 | 低 | 已有 `enterprise-summary` 端点可一次性获取，如未实现则前端缓存 |
