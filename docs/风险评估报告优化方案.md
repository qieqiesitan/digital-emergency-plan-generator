## 二、逐项差距分析

### 2.1 缺失表格（8 → 0）

参考文档使用了 8 个专业表格，系统生成一份都没有。这些表格是风险评估报告的核心专业价值所在：

**表格1：天然气理化特性及危害特性表**
- 内容：标识、主要组成、健康危害、急救措施、燃爆特性、泄漏应急、防护措施、理化性质、稳定性、毒性、环境资料、废弃处理、运输信息、法规信息
- 格式：31行 × 2列
- 作用：为后续"危险化学品有害因素辨识"提供数据基础

**表格2：柴油理化特性及危害特性表**
- 内容：同上结构
- 格式：31行 × 5列
- 作用：同上

**表格3：危险有害因素辨识汇总表**
- 内容：按"物质/自然条件/作业过程/设备设施"4 大辨识类型，分别列出对应事故类型
- 格式：5行 × 3列
- 作用：总览所有危险有害因素与事故类型的映射关系

**表格4：事故类型分布表**
- 内容：12 种事故类型 → 危险有害因素分布位置 → 危害后果 → 影响范围
- 格式：13行 × 5列
- 作用：将每种事故类型具体化到企业实际位置

**表格5：事故发生的可能性（L）分级标准**
- 内容：1-5 级，每级有具体行为/状态描述
- 格式：6行 × 2列
- 作用：统一 L 值判定标准，避免主观随意

**表格6：事故后果严重程度（S）分级标准**
- 内容：1-5 级，按"法律法规/人员/财产损失/停工/企业形象"5 维度描述
- 格式：6行 × 6列
- 作用：统一 S 值判定标准，多维度量化

**表格7：风险等级判定及控制措施**
- 内容：R=20-25→重大/15-16→较大/9-12→一般/<8→低，每级对应行动/期限
- 格式：5行 × 5列
- 作用：将风险值映射到明确的管理行动

**表格8：L×S 风险评估计算表**
- 内容：12 种事故类型 → L值 → S值 → R值 → 风险等级
- 格式：13行 × 6列
- 作用：最终量化结果一览表

### 2.2 L×S 评估方法不专业

**系统当前**：使用三级制（高/中/低 → 3分/2分/1分），R=L×S，最高9分，分三档（9-10重大/4-8较大/1-3一般）。

**参考文档**：使用五级制（1-5级），R=L×S，最高25分，分四档（20-25重大/15-16较大/9-12一般/<8低）。

五级制的优势：
- 区分度更高（25分 vs 9分满分，可区分更多中间状态）
- 与《企业职工伤亡事故分类》等国家标准推荐的 LEC 法思想一致
- 有明确的多维度 S 判定标准（法律/人员/财产/停工/形象）

### 2.3 危险化学品分析缺失

参考文档对天然气、柴油做了完整的 MSDS 式分析，包括：
- 理化特性（熔点、沸点、密度、闪点、爆炸极限等）
- 健康危害（侵入途径、健康影响）
- 燃爆特性（燃烧性、闪点、引燃温度、爆炸极限、危险特性、灭火方法）
- 泄漏应急处理
- 储运注意事项
- 防护措施

系统当前仅在企业信息中存有 hazardous_chemicals 字段，但 AI 生成时未做深度展开。

### 2.4 危险有害因素辨识维度不足

| 参考文档辨识维度 | 系统当前辨识维度 | 差距 |
|----------------|----------------|------|
| 危险化学品有害因素 | 物的因素（笼统） | 参考文档有 MSDS 级数据支撑 |
| 总平面布置及建（构）筑物 | 环境因素（笼统） | 参考文档分析到护栏、消防通道、防雷接地 |
| 配电设施 | 物的因素（笼统） | 参考文档分析到电流热量、电气火花、短路、电弧、雷电 |
| 消防设施 | 无专门分析 | 完全缺失 |
| 检维修施工过程 | 人的因素（笼统） | 参考文档按电气/高处/机械/中毒/爆炸细分 |
| 设备装置（电气/电梯/发电机/锅炉） | 物的因素（笼统） | 参考文档逐类设备分析 |
| 经营过程 | 人的因素+管理因素 | 参考文档按火灾/中毒/灼烫/触电/机械/坠落/打击/车辆细分 |

### 2.5 报告结构差异

**参考文档结构**（实际是一份"危险有害因素辨识分析"专题报告）：
- 封面
- 第一章 危险有害因素辨识分析（占80%+篇幅）
  - 1.1 危险化学品
  - 1.2 总平面及建筑物
  - 1.3 配电设施
  - 1.4 消防设施
  - 1.5 检维修施工
  - 1.6 设备装置
  - 1.7 经营过程
- 后续章节：事故类型汇总、L×S 评估、结论

**系统当前结构**（6章平均分配）：
- 一、评估目的与依据（~5%）
- 二、企业基本情况（~10%）
- 三、风险辨识（~25%）
- 四、风险等级评估（~25%）
- 五、管控措施评价（~20%）
- 六、结论与建议（~15%）

问题：风险辨识（最重要的章节）占比太少，缺少按物质/设备/工艺维度的细分。

### 2.6 语言风格差异

参考文档使用**正式公文语言**，每段有"综上所述，XX存在的危险因素有：XX"的结构化收尾。系统生成语言偏口语化/咨询报告风格，如"建议企业高度重视"等泛泛表述。

## 三、优化方案

### 阶段一：数据结构增强（后端+数据库）

#### 3.1.1 危险化学品表（新增）hazardous_chemicals 表

`sql
CREATE TABLE hazardous_chemicals (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    enterprise_id UUID NOT NULL REFERENCES enterprises(id) ON DELETE CASCADE,
    name VARCHAR(200) NOT NULL,              -- 化学品名称（天然气、柴油等）
    cas_no VARCHAR(50),                       -- CAS号
    un_no VARCHAR(20),                        -- UN编号
    physical_state VARCHAR(50),               -- 外观与性状
    flash_point VARCHAR(50),                  -- 闪点
    explosion_limit VARCHAR(50),              -- 爆炸极限
    ignition_temp VARCHAR(50),                -- 引燃温度
    density VARCHAR(50),                      -- 相对密度
    boiling_point VARCHAR(50),                -- 沸点
    health_hazard TEXT,                       -- 健康危害
    fire_hazard TEXT,                         -- 燃爆特性与消防
    leak_response TEXT,                       -- 泄漏应急处理
    storage_transport TEXT,                   -- 储运注意事项
    first_aid TEXT,                           -- 急救措施
    protective_measures TEXT,                 -- 防护措施
    location VARCHAR(300),                    -- 在企业内的存放/使用位置
    max_storage VARCHAR(100),                 -- 最大存储量
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

## 五、风险与注意事项

1. **AI 模型表格生成稳定性**：让 LLM 输出 HTML table 可能不稳定，需要后处理容错（如检测无 <table> 标签时回退到文本描述）。
2. **字符数控制**：原设 3000-5000 字的限制与新结构（含多个大表）冲突，建议调整为 5000-8000 字。
3. **向后兼容**：风险源 L/S 字段从文本改为整数需要数据迁移脚本。
4. **化学品数据来源**：用户需手动录入 MSDS 数据，考虑提供常见化学品预置模板。
