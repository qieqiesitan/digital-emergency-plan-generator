# 应急预案 DOCX 导出排版系统性优化 — 设计规格

> **日期**：2026-08-27 | **状态**：设计中 | **依赖**：PRD-07 文档导出模块（已上线）、docx_template.py（已上线）、GB/T 29639-2020

---

## 1. 概述

对应急预案 DOCX 导出（综合/专项/现场处置三类，走 `backend/app/services/docx_template.py` 链路）做一次系统性排版重构：以 GB/T 29639-2020 公文体例为基线重建样式体系，一次性修复纸张尺寸、边距、列表渲染错位、表格粗糙、缺失目录/页眉/页码、空白页等 11 类问题。

核心原则：**样式单一事实源（代码样式表）**、**封面保留用户认可的当前版式**、**渲染层修复对所有已有与新建预案立即生效**。

---

## 2. 背景与问题（诊断证据）

基于 3 份真实导出样本（综合/专项/现场处置）+ 参考文档《紫楹台酒店应急预案》的审计结果：

| # | 问题 | 证据 |
|---|------|------|
| 1 | 纸张为 Letter（21.59×27.94cm）而非 A4 | python-docx 默认模板未改页面尺寸 |
| 2 | 封面节边距（3.7/3.5/2.8/2.6）与正文节边距（2.54/2.54/3.18/3.18）不一致 | Section 0 vs Section 1 |
| 3 | 无目录、无页眉、无页脚页码 | PRD-07 明确要求；PDF 全 277 页无页眉/页码 |
| 4 | 362 个长段落被渲染为 List Bullet（项目符号 + 悬挂缩进 -14.2pt） | html_to_docx_content 的 ul/li 分支无条件转列表 |

| 元素 | 字体 | 字号 | 其他 |
|------|------|------|------|
| 正文大标题 | 宋体加粗 | 22pt | 居中 |

| 项目 | 规范 |
|------|------|

| 目录 | 位于批准页之后；"目　　录"黑体 18pt 居中 + TOC 域（TOC \o "1-3" \h \z \u），Word/WPS 打开后 F9 刷新 |

| 页脚 | 宋体 10.5pt 居中：第 X 页 共 Y 页（PAGE/NUMPAGES 域） |

| 分页 | 一级章节用 page_break_before（替代手动 add_page_break，消除连续空白页）；封面/目录后保留手动分页 |

## 5. 渲染逻辑改造

### 5.1 register_all_styles — 样式注册重构

完整定义以下样式（删除散落硬编码，渲染分支只引用样式）：

- Normal：仿宋 16pt（eastAsia），西文 Times New Roman，两端对齐，固定 28 磅行距，段前段后 0
- Heading 1-6：按 4.3 表（黑体/楷体/仿宋 + 首行缩进 2 字符 + 段前 28/6pt）
- Body Text：仿宋 16pt，首行缩进 2 字符，两端对齐，固定 28 磅
- Cover Title / Cover Sign / Body Title：按 4.2/4.3 表（保留现有样式名，调整参数）
- 新增 Plan Table 表格样式：表头底纹、12pt、固定 22 磅
- 新增 Caption 图题样式：宋体 14pt 居中
- 页眉/页脚样式：宋体 10.5pt 居中
- 目录样式：TOC Heading 黑体 18pt 居中；toc 1-3 仿宋 14/12pt、页码右对齐点线（用 Word 默认 TOC 域渲染，样式名 toc 1-3 兜底）

### 5.2 generate_plan_docx — 主流程

1. 页面设置统一 A4 + 公文边距（不再分封面/正文两套）。
2. build_cover 的 doc_title 用传入的 plan_title，删除硬编码"生产安全事故应急预案"。
3. 封面节设置 different_first_page=True；批准页、目录页在同一节。
4. 批准页后插入目录页：黑体 18pt"目　　录" + TOC 域，末尾分页。
5. 页眉/页脚写入封面节，正文节 header.is_linked_to_previous = True 继承。
6. 一级章节标题段落设置 page_break_before=True，删除手动 doc.add_page_break()（保持节内连续排版，消除满页产生的空白页）。
7. 删除 builtins.print 调试语句。

### 5.3 html_to_docx_content — 内容渲染

- 标题：add_heading 引用 Heading 1-6 样式。
- 段落：p → Body Text 样式（不再逐段设置首行缩进）。
- 列表（核心修复）：新增常量 LI_TEXT_THRESHOLD = 30；对每个 li 取纯文本：
  - len(text) <= 30 → List Bullet / List Number 样式（固定 28 磅、仿宋 16pt）；
  - len(text) > 30 → Body Text 正文段落（去除 - / • 前缀，首行缩进，无项目符号）。
- 表格：走 build_table 统一渲染（见 5.4）。
- blockquote / pre / hr / div：保留现有行为，引用样式。

### 5.4 build_table — 列宽分配与表头

1. 计算各列内容宽度：char_units = max(表头字数, 各单元格最大字数)，中文按 1 单位、西文按 0.5 单位估算。
2. 列宽 = 单位数按比例映射到正文区宽（15.6cm），限制最小 1.5cm / 最大 6cm，合计不足补到最后一列。
3. 表头行：加浅灰底纹（w:shd fill=D9D9D9）、12pt 加粗、居中。
4. 单元格：12pt、固定 22 磅；列内平均字符数 <= 6 的列居中，其余左对齐。
5. 表格居中，前后各留一个空段落（保持现有结构）。

### 5.5 图片与图题

1. Mermaid PNG 与疏散图 PNG 统一居中、宽度自适应（min(原宽, 14.6cm)）。
2. 图题：全文档连续编号（图 1、图 2…）。
   - Mermaid 图：图 N 流程图；
   - 疏散图：按 diagram_svgs key 映射中文名（evacuation → 人员疏散路线示意图，evacuation_1 → 1 层人员疏散路线示意图 等），映射缺失时用 图 N 示意图。
3. 图题段落用 Caption 样式（宋体 14pt 居中），紧贴图片下方。

### 5.6 签署页

保留现有结构，表头/单元格改用 Plan Table 样式规范（12pt、底纹）。

## 6. 边界处理

| 场景 | 处理 |
|------|------|
| 空章节 | 跳过（保留现有行为） |
| Mermaid 渲染失败 | 保留占位文字（现有行为） |
| 表格无数据行 | 仅表头 + 跳过 |
| 超长单元格 | 列宽封顶 6cm，内容自动换行 |
| 列表项阈值判定 | LI_TEXT_THRESHOLD 常量，便于微调 |
| 无 plan_title / plan_number | 沿用现有兜底（编号为空则不显示右上角行） |
