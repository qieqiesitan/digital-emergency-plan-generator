## 问题

### 必须修复

1. **撤销一步滞后（实测确认）**：store 的 `commit()` 在 `setSnapshot()` 之后调用，会把“变更后”状态推入 `past`（`riskMappingWorkbenchStore.ts:73`）。组件全部按“先 setSnapshot 后 commit”使用（`WorkbenchCanvas.tsx:81/103`、`WorkbenchPropertiesPanel.tsx:31` 等），导致 undo 第一次点击不产生任何回退。我用临时 vitest 复现：一次添加待绑定区域后 `undo()`，区域仍在（期望消失）；两次操作后需按 3 次 undo 才能全部撤销。既有测试之所以全绿，是因为测试里 `setSnapshot` 与 `commit` 分离调用，掩盖了组件用法下的时序问题。建议把 `commit` 语义改为“在变更前快照”（组件先 `commit` 再 `setSnapshot`，或 store 内部支持变更前快照），并补一条“组件实际调用序列”的回归测试。

2. **删除分区会遗留孤儿风险点，直接破坏保存**：分区删除只从 `zones` 移除（`WorkbenchZonePanel.tsx:60`、`WorkbenchPropertiesPanel.tsx:116`），不处理其下风险点的 `zone_id`。这些风险点仍留在 `riskPoints` 里：若分区已持久化，保存时后端 `existing_points` 里该风险点的 `zone_id` 指向被删分区，`missing_zone_ids` 校验直接 422；若分区是新建的，风险点 `zone_id` 是 `new-zone-*` 客户端 ID，后端 `created_zone_map` 无此 key，抛 `ZONE_NOT_FOUND`。删除分区时必须同时解绑/回收其风险点（提示用户或一并标记删除）。

### 重要

3. **切换楼层/删除楼层静默丢弃未保存改动**：楼层切换把 `dirty` 强制置 false 并清空 `deletedZoneIds`/`deletedRiskPointIds`（`EnterpriseFloorManager.tsx:85/97`），已绘制内容随查询重新加载被覆盖，无任何确认。画布工作流中这是高概率数据丢失场景，建议至少加 Popconfirm/未保存提示。

4. **删除新建风险点会把客户端 ID 塞进 `deleted_risk_point_ids`**：`WorkbenchPropertiesPanel.tsx:134` 对新建点（`new-point-*`）也追加删除 ID，与分区的 `isPersisted` 防护不对称。当前后端对不存在的 ID 静默忽略（`risk_management.py:377`）所以不炸，但语义错误且依赖后端容错，应与分区逻辑对齐。

5. **平面图底图拉伸失真，未用画布尺寸**：`KonvaImage` 固定拉伸到 1200×900（`WorkbenchCanvas.tsx:116`），忽略 `canvas_width`/`canvas_height` 和图片原始比例，宽幅厂房平面图会被压扁，绘制的区域与实际位置对不上。建议按原始尺寸等比缩放居中，并让 Stage 尺寸/网格跟随 `canvas_width`/`canvas_height`（当前网格行数也是按 1200×900 硬编码）。

6. **撤销/重做后 dirty 永远为 true**：`undo`/`redo` 无条件置 `dirty: true`（`riskMappingWorkbenchStore.ts:79/91`），即使完全回退到保存点，保存按钮仍可点，且会带着旧 `floor_updated_at` 发请求触发 SAVE_CONFLICT。建议与上次保存快照比对来决定 dirty。

### 次要 / 仅供参考

7. `bindFirstPending` 是“改分区 + 移除待绑定区域”两步，每次各 commit 一次，undo 会拆成两步且第一步撤销不了第二步（一次性变更被分散）；且待绑定区域从画布上移除要等下次请求才生效，建议作为单次原子操作处理。
8. 分区多边形 `draggable` 但没有 `onDragEnd` 持久化（`WorkbenchCanvas.tsx:157`），拖动位置在重新渲染/刷新后丢失，与保存结果不一致；rect 拖拽预览固定 100×100（规格审查已提示）。
9. `guideEnabled` 开关有 UI 无任何行为；`guide` 逻辑尚属后续任务，可先隐藏或禁用。
10. 文字标注“双击编辑文字”只是占位文案，双击实际无编辑行为；事件处理多用 `any`（`WorkbenchCanvas.tsx` 多处），可换 `KonvaEventObject<MouseEvent>` 等类型。
11. `apiErrorMessage` 在 `EnterpriseFloorManager.tsx` 与 `RiskMappingWorkbenchPage.tsx` 重复实现，可提取公共工具。
