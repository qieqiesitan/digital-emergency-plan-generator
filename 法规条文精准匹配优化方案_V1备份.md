# 法规条文精准匹配 — 优化方案

> 版本: V1.0 | 日期: 2026-07-17 | 状态: 待确认

---

## 一、问题诊断

### 1.1 根本症结

当前系统的条文检索链路是一条**「法规级粗放管道」**。从 `index.yaml` 到 `context_builder`，每次生成章节时，系统做的是：

```
section_key → 匹配法规ID → 读{regulation_id}.md → 返回全部条文
```

它不做**条文级别**的独立索引、独立评分、独立召回。AI 拿到的是整部法规的全部条文（最多 `max_articles=30`），靠 prompt 指令自行筛选。

**代码证据**（[retriever.py](/C:/Users/55061/Documents/数字化预案自动生成 2/backend/app/regulations/retriever.py)）：

```python
# 第 89-101 行：全量加载条文
for reg in plan_result.get("effective", []):
    articles = self._load_articles(reg)  # ← 返回全部条文，不做过滤
    # ...
    for art in articles:
        if article_count >= max_articles:
            break
        trimmed.append(art)
        article_count += 1
```

向量库已经按条文 ID（`{regulation_id}_{article_number}`）做了独立索引（[vector_store.py](/C:/Users/55061/Documents/数字化预案自动生成 2/backend/app/regulations/vector_store.py:63)），但 `retriever.py` 仅把它当作兜底补充（≥30 条才启用），且返回的是整个法规节点而非单条条文。

### 1.2 精度瓶颈逐层分析

| 检索层 | 当前做法 | 精度问题 |
|--------|---------|---------|
| plan_type → 法规 | `index.yaml` 静态 ID 列表 | ✅ 精确但静态，新法规需人工加 |
| section → topic | `section_topics.yaml` 正则 → topic 标签 → 图谱查询 | ⚠️ 依赖 AI 解析的 topic 标注质量；标注错误则匹配缺失 |
| topic → 条文 | 无：返回整部法规所有条文 | 🔴 **核心缺口**：100 条文中只有 5 条相关，AI 照样收到 100 条 |
| vector 语义补充 | 仅兜底（≥30 条启用），返回法规级节点 | 🔴 最精确的信号被当作边角料 |
| 条文文件加载 | `_load_articles()` 用文件名/标题做启发式匹配 | ⚠️ 可能加载错误内容 |

### 1.3 量化评估

对一个典型场景（`comprehensive` 预案 × `sec_响应处置` 章节）：

- 匹配到法规：6 部 × 平均 60 条 = **360 条条文**注入 prompt
- 实际相关条文：约 **12-18 条**（响应程序、处置措施、应急资源调用）
- **噪音比**：~95%
- 向量库按条文索引但只取 top-5 个 regulation node，放弃了对 360 条条文各自打分的机会

## 二、目标架构

### 2.1 核心设计原则

1. **条文是一等实体**：每条条文有独立 ID、独立图谱节点、独立向量
2. **混合检索做主路径**：图谱精确 + 向量语义 **并行召回**，在条文级合并打分，而非串行兜底
3. **按相关性截断**：按 `(topic_match_score * 0.4 + vector_similarity * 0.4 + mandatory_bonus * 0.2)` 排序取 Top-K
4. **保持向后兼容**：不破坏现有 API，旧方法标记 deprecated 保留

### 2.2 目标数据流

```
法规入库 (sync.py)
  │
  ├─→ 图谱写入（法规节点 + topics边 + refs边）
  │     └─→ 法规节点: {id, code, topics, ...}
  │
  └─→ 条文级写入
        ├─→ texts/{reg_id}.md          (保持不变，向后兼容)
        ├─→ 向量索引: id = art_{reg_id}_{article_number}
        │               text = 条文全文
        │               metadata = {regulation_id, regulation_code, topics, article_number, article_title}
        └─→ 图谱子节点 (NEW): id = art_{reg_id}_{article_number}
                             node_type = "article"
                             label = "第X条"
                             parent_regulation = reg_id

预案生成 (_build_section_prompt)
  │
  ├─→ RegulationContextBuilder.build_for_plan()
  │     └─→ retriever.retrieve_articles(plan_type, section_key, section_title, enterprise_data)
  │           │
  │           ├─→ Step 1: 图谱精准召回
  │           │     ├─→ query_by_plan_type() → 候选法规列表
  │           │     ├─→ 遍历候选法规的子节点 → 收集所有 article 节点
  │           │     └─→ 过滤：topic 匹配 + 非废止 → 候选条文集 A
  │           │
  │           ├─→ Step 2: 向量语义召回 (并行)
  │           │     ├─→ 构建查询向量: section_title + section_key + enterprise.industry + plan_type
  │           │     ├─→ vector_store.search(query, top_k=20)
  │           │     │      metadata 已含 topics → 二次过滤
  │           │     └─→ 候选条文集 B
  │           │
  │           ├─→ Step 3: 合并去重 + 打分排序
  │           │     ├─→ A ∪ B，按 normalized_id 去重
  │           │     ├─→ 逐条计算 relevance_score
  │           │     └─→ 排序取 Top-K (K = min(15, token_budget/avg_article_len))
  │           │
  │           └─→ Step 4: 按法规分组 → 注入 prompt
  │
  └─→ prompt += formatted_articles (按 law 分组，含编号+条文原文+引用路径)
```

### 3.2 修改：`regulations/graph.py` — 新增 article 子节点

```python
# 在 RegulationGraph 中新增方法

def add_article_node(self, regulation_id: str, article: dict) -> str:
    """为法规节点添加条文子节点。article = {number, text, topics}"""
    article_id = f"art_{regulation_id}_{article['number']}"
    node = {
        "id": article_id,
        "label": article["number"],
        "full_name": article.get("title", article["number"]),
        "node_type": "article",
        "article_number": article["number"],
        "article_text": article["text"],
        "parent_regulation": regulation_id,
        "topics": article.get("topics", []),
        "status": "effective",
    }
    self.add_node(node)
    # 建立父子边
    self._g.add_edge(article_id, regulation_id, relation="属于")
    self.save()
    return article_id

def get_articles_by_regulation(self, regulation_id: str) -> list[dict]:
    """获取某法规的所有条文子节点。"""
    articles = []
    for nid, data in self._g.nodes(data=True):
        if data.get("node_type") == "article" and data.get("parent_regulation") == regulation_id:
            node = dict(data); node["id"] = nid
            articles.append(node)
    return sorted(articles, key=lambda a: a.get("article_number", ""))

def get_articles_by_topic(self, topic: str, limit: int = 50) -> list[dict]:
    """按主题标签查询条文。"""
    results = []
    for nid, data in self._g.nodes(data=True):
        if data.get("node_type") != "article":
            continue
        if topic in (data.get("topics") or []) and data.get("status") != "abolished":
            node = dict(data); node["id"] = nid
            results.append(node)
            if len(results) >= limit:
                break
    return results

def query_articles_by_plan_type(self, plan_type: str) -> dict:
    """新增方法：按预案类型查询法规 → 展开条文子节点。"""
    plan_regs = self.query_by_plan_type(plan_type)
    article_regs = []
    for reg in plan_regs.get("effective", []):
        articles = self.get_articles_by_regulation(reg["id"])
        if articles:
            reg_copy = dict(reg)
            reg_copy["articles"] = articles
            article_regs.append(reg_copy)
    plan_regs["effective"] = article_regs
    return plan_regs
```

## 四、Phase 2：条文级检索管道重写

这是核心改造，需要重写 `retriever.py`，让 `context_builder.py` 和 `injector.py` 接入新管道。

### 4.1 重写：`regulations/retriever.py`

```python
class RegulationRetriever:
    def __init__(self, graph, vector_store, scorer=None):
        self.graph = graph
        self.vector_store = vector_store
        self.scorer = scorer or ArticleRelevanceScorer()

    # ── 新增核心方法 ──

    def retrieve_articles(
        self,
        plan_type: str,
        section_key: str = "",
        section_title: str = "",
        enterprise_data: dict = None,
        max_articles: int = 15,
    ) -> dict:
        """
        条文级混合检索 —— 新主路径。

        返回:
          {
            "articles": [ScoredArticle],          # 按分数降序
            "by_regulation": {reg_id: [ScoredArticle]},  # 按法规分组
            "debug": { "graph_count": N, "vector_count": M, "merged_count": K }
          }
        """
        section_topics = _match_section_topics(section_key, section_title)
        graph_candidates = self._graph_article_recall(plan_type, section_topics)
        vector_candidates = self._vector_article_recall(
            plan_type, section_key, section_title,
            section_topics, enterprise_data,
        )

        # 合并去重
        all_candidates = self._merge_dedup(graph_candidates, vector_candidates)

        # 打分排序
        scored = self.scorer.score_articles(all_candidates, section_topics)
        scored.sort(key=lambda s: s.score, reverse=True)

        # 截断
        top = scored[:max_articles]

        # 按法规分组
        by_reg = {}
        for sa in top:
            rid = sa.candidate.regulation_id
            by_reg.setdefault(rid, []).append(sa)

        return {
            "articles": top,
            "by_regulation": by_reg,
            "debug": {
                "graph_count": len(graph_candidates),
                "vector_count": len(vector_candidates),
                "merged_count": len(all_candidates),
            },
        }

    def _graph_article_recall(
        self, plan_type: str, section_topics: list[str]
    ) -> list[ArticleCandidate]:
        """图谱侧召回：plan_type → 法规 → 条文子节点 + topic过滤。"""
        plan_regs = self.graph.query_by_plan_type(plan_type)
        candidates = []
        for reg in plan_regs.get("effective", []):
            articles = self.graph.get_articles_by_regulation(reg["id"])
            for art in articles:
                art_topics = art.get("topics", [])
                # topic 过滤：如果 section 有 topic 要求，条文 topic 必须命中
                if section_topics and not any(t in art_topics for t in section_topics):
                    continue
                candidates.append(ArticleCandidate(
                    id=art["id"],
                    regulation_id=reg["id"],
                    regulation_code=reg.get("code", ""),
                    regulation_name=reg.get("full_name", reg.get("label", "")),
                    article_number=art.get("article_number", art.get("label", "")),
                    article_text=art.get("article_text", ""),
                    topics=art_topics,
                    vector_similarity=0.0,
                    is_core=reg.get("is_core", False),
                    is_abolished=reg.get("status") == "abolished",
                ))
        return candidates

    def _vector_article_recall(
        self, plan_type, section_key, section_title,
        section_topics, enterprise_data,
    ) -> list[ArticleCandidate]:
        """向量侧召回：构建 query → embedding 搜索 → 构造 ArticleCandidate。"""
        if not self.vector_store or self.vector_store.collection_count() < 5:
            return []

        query = self._build_semantic_query(enterprise_data or {}, plan_type,
                                           section_title)
        results = self.vector_store.search_articles(
            query, section_topics=section_topics, top_k=20,
        )

        candidates = []
        for item in results:
            meta = item.get("metadata", {})
            reg_id = meta.get("regulation_id", "")
            reg_node = self.graph.get_node(reg_id) or {}
            # 跳过无法关联到图谱节点的情况
            if not reg_node:
                continue
            candidates.append(ArticleCandidate(
                id=f"art_{reg_id}_{meta.get('article_number', 'unknown')}",
                regulation_id=reg_id,
                regulation_code=reg_node.get("code", ""),
                regulation_name=reg_node.get("full_name", reg_node.get("label", "")),
                article_number=meta.get("article_number", ""),
                article_text=item.get("text", ""),
                topics=meta.get("article_topics", meta.get("regulation_topics", [])),
                vector_similarity=1.0 / (1.0 + item.get("distance", 0)),  # cosine → similarity
                is_core=reg_node.get("is_core", False),
                is_abolished=reg_node.get("status") == "abolished",
            ))
        return candidates

    def _merge_dedup(self, graph_candidates, vector_candidates) -> list[ArticleCandidate]:
        """按 normalized_id 去重，向量相似度取 max。"""
        merged = {}
        for c in graph_candidates:
            key = self._normalize_id(c.id)
            merged[key] = c
        for c in vector_candidates:
            key = self._normalize_id(c.id)
            if key in merged:
                merged[key].vector_similarity = max(
                    merged[key].vector_similarity, c.vector_similarity
                )
            else:
                merged[key] = c
        return list(merged.values())

    def _normalize_id(self, article_id: str) -> str:
        """规范化 ID，消除 '_第' vs '_第X' 的差异。"""
        import re
        return re.sub(r'[\s_]', '', article_id).lower()

    # ── 保留旧方法（向后兼容） ──

    def retrieve(self, plan_type, section_key="", enterprise_data=None,
                 max_articles=30):
        """旧接口，保持兼容，内部委托给新方法。"""
        result = self.retrieve_articles(plan_type, section_key,
                                         enterprise_data=enterprise_data,
                                         max_articles=max_articles)
        # 转换为旧格式
        ...
        return {"effective": ..., "abolished": ...}

    def retrieve_by_topics(self, section_key, section_title,
                           plan_type="", max_articles=20):
        """旧接口，保持兼容。"""
```

### 4.2 修改：`regulations/context_builder.py`

```python
def get_chapter_context(self, section_key="", section_title="",
                        plan_type="", enterprise_data=None):
    """改用新检索管道。"""
    retriever = get_retriever()
    result = retriever.retrieve_articles(
        plan_type=plan_type,
        section_key=section_key,
        section_title=section_title,
        enterprise_data=enterprise_data,
    )

    if not result["articles"]:
        return "【法规检索暂时不可用，本章节按通用规范编写】"

    return self._format_article_context(result["by_regulation"], section_key, section_title)

def _format_article_context(self, by_regulation, section_key, section_title):
    """按法规分组格式化条文上下文。"""
    is_basis = self._is_basis_section(section_key, section_title)
    lines = ["【编制依据——本章必须包含以下法律法规的完整名称和文号】" if is_basis
             else "【法规写作纲要——本节必须覆盖以下法规要求的关键条款】", ""]

    total_chars = 0
    max_chars = BASIS_MAX_CHARS if is_basis else MAX_CONTEXT_CHARS

    for reg_id, scored_articles in by_regulation.items():
        if not scored_articles:
            continue
        sa0 = scored_articles[0]
        header = f"### {sa0.candidate.regulation_name}"
        if sa0.candidate.regulation_code:
            header += f"（{sa0.candidate.regulation_code}）"
        lines.append(header)
        total_chars += len(header)

        for sa in scored_articles[:8]:  # 每部法规最多 8 条
            art = sa.candidate
            line = (f"- **{art.article_number}** {art.article_text[:200]}"
                    + (f"  [相关性: {sa.score:.2f}]" if sa.score < 0.5 else ""))
            if total_chars + len(line) > max_chars:
                lines.append("(以下条文因篇幅限制省略)")
                break
            lines.append(line)
            total_chars += len(line)
        lines.append("")

    lines.extend(["", "【写作要求】",
        "- 正文须体现上述法规条款的具体要求",
        "- 在行文中自然提及法规名称和具体条款号",
        "- 如某条文与本节不直接相关，可以不使用"])
    return "\n".join(lines)
```

```python
class CrossReferenceDetector:
    """检测条文间的交叉引用关系，建立图边。"""

    REFERENCE_PATTERNS = [
        r'（参照|参见|依据|按照|执行|适用）[《〈]?(?P<law_name>[^）〉]*?[》〉]?\s*(?:第\s*(?P<article_num>[一二三四五六七八九十百\d]+)\s*条)?',
        r'(?P<article_num>第[一二三四五六七八九十百\d]+条)\s*的?规定',
    ]

    def detect_references(self, article_text: str) -> list[dict]:
        """
        从条文文本中提取引用的其他法规/条文。
        返回: [{"law_name": "安全生产法", "article_num": "第二十一条", "confidence": 0.82}, ...]
        """

    def resolve_references(self, references: list[dict],
                           all_regulations: list[dict]) -> list[dict]:
        """将引用的法规名称解析为具体的 regulation_id 和 article_id。"""

    def build_reference_graph(self, article_id: str,
                              resolved_refs: list[dict]) -> None:
        """在图中建立 article→article 的引用边。"""
```

## 十、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| ChromaDB 大规模查询性能下降 | 低 | 中 | 条文级搜索 top_k 控制在 20，图谱侧先过滤 |
| AI 解析的 topics 不准确导致匹配缺失 | 中 | 中 | Phase 3 加入 TopicValidator；section_topics.yaml 扩展关键词覆盖 |
| 旧数据（无 article 子节点）与新管道不兼容 | 高 | 低 | 迁移脚本 + `_load_articles` 保留兜底 |
| 权重参数（W_TOPIC 等）调参偏差 | 中 | 中 | scorer 权重可配（读配置文件），初始值基于经验设定 |
| 条文级向量索引使 ChromaDB 体积膨胀 | 低 | 低 | 按 regulation_id 做 logical partitioning，支持单独重建 |

## 十二、验收标准

1. 对一个 `comprehensive` 预案 × `sec_响应` 章节，prompt 中注入的条文数从「全部 360 条」降至「精选 12-18 条」，每条附带引用法规名称和条款号
2. 向量语义搜索**始终启用**（不再受 `≥30` 限制），作为主路径的并行分支
3. 新法规入库后，自动归类到对应预案类型的 `index.yaml`（人工可覆盖）
4. 条文废止时，生成的 prompt 不包含已废止条文
5. 所有旧 API 接口返回格式不变，现有生成流程无感切换
