### docx 渲染服务

`backend/app/services/risk_notice_card_docx.py`：

* `make_qr_png(url: str) -> bytes`：用 qrcode 库生成二维码 PNG bytes（`qrcode.make(url)` 后 save PNG）。若 qrcode 依赖 Pillow，确认 Pillow 已安装或 requirements 加 `qrcode[pil]`。
* `render_cards_docx(cards: list[CardData], out_path: str, sign_pngs: dict[str, bytes])`：A4 竖版、每卡一页。
  * 头部三区：企业名（左）/ 居中标题「{name}安全风险告知卡」/ 右上角二维码 PNG（约 1.4cm）
  * 左栏：等级色带 + 键值表格 6 行（名称/编号/等级/责任单位/责任人/电话）+ 「安全标志」标题 + 标志 PNG（约 1.5cm，带名称文字）
  * 右栏：四个信息块（主要危险因素描述 / 主要事故类型【GB 6441 标注】/ 主要风险控制措施 / 应急处置措施），标题加粗深色
  * 页脚：签发单位（企业名）/ 编制日期 / 版本（V1.0 或 V1.{version}）
  * 卡之间 `doc.add_page_break()`
* SVG 转 PNG：python-docx 的 add_picture 不支持 SVG。优先复用 `mermaid_renderer.render_svg_to_png(svg_content)`（async，返回 bytes）；若其依赖过重，评估后用 cairosvg（若已安装）直接转换。选择以「测试能通过且不引入重依赖」为准，导出端点在 async 上下文中调用。
* 导出端点：`POST /export`，body `{object_ids: list[str]}`，逐卡查归属 + build_card_data（不存在的卡跳过并记 warnings），生成标志 PNG，渲染 docx 到 `settings.EXPORT_DIR`，文件名 `risk-notice-{enterprise_id[:8]}-{YYYYMMDDHHMMSS}.docx`，返回 `{file_key}`；无卡可导返回 400。
