### 需要修复的问题（用户实测发现）

**1. C1 跨章节总指挥姓名不一致——严重误报**

当前正则 `(?<!副)总指挥\s*[：:为是]?\s*([\u4e00-\u9fa5]{2,4})(?=[，。；;、\s]|$)` 把「总指挥不在岗时」「总指挥职责」「总指挥负责制」「总指挥下达指令后」「总指挥接报后」「总指挥组织讲评」等后续 2-4 字当成了姓名。

修复方案（组合）：

a. 停用词表补全：`_NAME_STOPWORDS` 增加 `"不在岗时","职责","负责制","指令后","接报后","组织讲评","下达","代行","命令"` 等常见非姓名词。

b. 更稳健：要求「职务名后必须有分隔符（：/: /为/是/（/(）」才捕获姓名。当前 `[：:为是]?` 是可选的，导致「总指挥不在岗时」被捕获。改为：职务后先尝试匹配分隔符再捕获姓名，无分隔符时跳过：

```python
    ROLE_PATTERNS = [
        (r"(?<!副)总指挥\s*[：:为是（(]\s*([\u4e00-\u9fa5]{2,4})(?=[，。；;、\s）)]|$)", "总指挥"),
        (r"副总指挥\s*[：:为是（(]\s*([\u4e00-\u9fa5]{2,4})(?=[，。；;、\s）)]|$)", "副总指挥"),
        (r"安全负责人\s*[：:为是（(]\s*([\u4e00-\u9fa5]{2,4})(?=[，。；;、\s）)]|$)", "安全负责人"),
    ]
```

注意：`[：:为是（(]` 后跟 `\s*` 再捕获姓名；「总指挥（刘昕野）」与「总指挥：刘昕野」都覆盖；「总指挥不在岗时」因无分隔符不捕获。验证现有测试 `test_c1_verb_not_matched_as_name` 等仍通过，并补充「总指挥不在岗时」「总指挥职责」不误报的测试。

c. **组长不参与跨章节比对**：从 `ROLE_PATTERNS` 中移除「组长」——组长是小组级职务，不同小组组长不同是正常配置，不应全局比对。保留总指挥/副总指挥/安全负责人（唯一职务）。

**2. C1 与档案比对：总经理兼任总指挥应视为满足**

当前 org_names 用 `role in (position or "") or role in (role or "")` 精确匹配，「总经理」不匹配「总指挥」→ 误报「正文总指挥与企业组织架构不符」。

修复：新增语义映射，总经理→总指挥、副总经理→副总指挥：

```python
def _role_matches(member: dict, role: str) -> bool:
    """判断成员是否承担某角色：职务名直接匹配，或总经理→总指挥/副总经理→副总指挥。"""
    pos = (member.get("position") or "") + (member.get("role") or "")
    if role in pos:
        return True
    if role == "总指挥" and "总经理" in pos:
        return True
    if role == "副总指挥" and "副总经理" in pos:
        return True
    return False
```

C1 的 org_names 构建改用 `_role_matches`；E2 的 org_roles 构建同样改用 `_role_matches`（判定是否含总指挥/副总指挥）。注意 E2 应保持「总经理→总指挥、副总经理→副总指挥」都算满足。

**3. C3 响应分级——排除数量表述**

当前 `has_chinese = 一(?:级|类)(?:应急)?响应|二(?:级|类)...|三(?:级|类)...` 会把「本预案设置三级响应」「将火灾应急响应分为三级」中的「三级响应」当成级别名。

修复：负向前瞻排除「设置/分为/设/划分」等数量表述：

```python
    has_chinese = bool(re.search(
        r"(?<!设置)(?<!分为)(?<!划分)一(?:级|类)(?:应急)?响应"
        r"|(?<!设置)(?<!分为)(?<!划分)二(?:级|类)(?:应急)?响应"
        r"|(?<!设置)(?<!分为)(?<!划分)三(?:级|类)(?:应急)?响应",
        full_text,
    ))
```

同时保留 has_roman 检测不变。补充测试：「本预案设置三级响应」不触发，「启动一级应急响应」触发。

**4. C3 时限——删除全局分钟/小时比对**

当前把全文所有分钟/小时数值做等价比对，导致「持续观察 30 分钟」（普通火灾）与「观察时间延长至 2 小时」（锂电池）这两个独立场景被误报「数值不对应」。

修复：**删除该规则**（纯正则无法判断是否同一场景的时限，误报大于价值）。在代码中移除 min_vals/hr_vals 比对块，并在规格文档同步标注「时限混用检查已移除（无法可靠判断同一场景）」。

**5. E3 资源数量为 0——粒度修正**

当前对「类别下任一资源 quantity==0」报「{类别}应急资源数量为 0」，导致「公安机关」类明明有明光路派出所 1 条，只因属地派出所 0 就被报整类为 0。

修复：仅当**类别下所有资源数量均为 0（或无有效条目）**才报类别级：

```python
    # E3 第 3 条：类别下所有资源数量均为 0 时提示
    if has_risk:
        cat_quantities: dict[str, list] = {}
        for r in resources:
            cat = getattr(r, "category", "") or r.get("category", "")
            q = getattr(r, "quantity", None) if hasattr(r, "quantity") else r.get("quantity")
            cat_quantities.setdefault(cat, []).append(q)
        for cat, qs in cat_quantities.items():
            if cat and qs and all(q == 0 for q in qs if q is not None) and not any(q is not None and q > 0 for q in qs):
                warnings.append({
                    "section_key": "",
                    "section_title": "",
                    "warning": f"{cat}应急资源数量均为 0",
                })
```

（「均有 0 且无正数」才报；None 视为未知不参与。现有 `test_e3_zero_quantity_resource_warning` 需适配：单一资源 quantity=0 → 仍报；补充「同类别有正数资源时不报」测试。）
