## 关键契约

**状态机**（HazardRecord.status 值域：registered/grading/pending_approval/rectifying/reviewing/second_review/closed）：

```python
TRANSITIONS = {
    "registered": {"grade"},
    "grading": {"rectify", "pending_approval"},
    "pending_approval": {"rectify"},
    "rectifying": {"review"},
    "reviewing": {"close", "rectify"},          # pass→close / fail→退回
    "second_review": {"close", "rectify"},
}

ROLE_GATE = {
    "grade": {"enterprise_admin"},
    "pending_approval": {"enterprise_admin"},   # 重大挂牌（与 grade 同一步触发时按流程）
    "rectify": {"rectifier", "enterprise_admin"},
    "review": {"reviewer", "enterprise_admin"},
    "close": {"enterprise_admin"},
}

def can_transition(record, action, actor_role, strict_mode: bool) -> tuple[bool, str]:
    """校验：动作在 TRANSITIONS[status] 中；role 满足 ROLE_GATE；
    review 时 actor 必须是指定 reviewer 且 ≠ rectifier（reviewer_user_id 与 rectification_user_id 不同，否则 422 语义）；
    close 时严格模式+重大 必须先 second_review（即 status==second_review 才能 close）；返回 (ok, reason)。"""

async def apply_transition(db, record, action, actor_user, actor_role, payload, enterprise) -> HazardRecord:
    """can_transition 校验 → 按 action 更新字段：
    grade: level/hazard_type/grading_basis/deadline（字典 deadline_rules）/rectification_plan（重大必填）→ status=rectifying（一般）或 pending_approval（重大）
    pending_approval 由审批动作 approve/reject 处理：approve→rectifying；reject→grading（或 registered，选语义清晰方案并说明）
    rectify: rectification 记录写入 hazard_rectifications + evidence → status=reviewing（指定 reviewer）
    review: result=pass→（严格+重大→second_review 否则 close）；fail→退回 rectifying
    close: status=closed、closed_at=now
    每个 action 写 hazard_audit_logs（action 名 + detail 含变更）。"""
```

**企业配置**：`hazard_closure_mode`（standard/strict）读取自 Enterprise（模型未同步列时任务 3 补列或本任务读 SQL 列；若 ORM 无该列，本任务先加 Enterprise 模型 4 列——`hazard_closure_mode`/`hazard_public_token`/`hazard_report_token`/`hazard_config`，属必要补充）。
