**调度器**：`AsyncIOScheduler`（apscheduler 3.x），每 5 分钟执行一次 `run_hazard_scans(db)`（可注入 session factory 或依赖，报告实现）。三个扫描函数尽量独立、可单独测试：

**① 到期计划生成任务**

- 扫描 enabled=True 的计划，按 frequency 判断今天是否到期（daily 每天；weekly/custom 按 weekdays 含今天；monthly 按每月 1 日——与 `hazard_service.generate_tasks_for_plan` 约定一致）。
- 调用 `generate_tasks_for_plan(db, plan, date.today())`（防重已内置：同 plan 同日已有任务返回 None）。
- 报告说明：扫描全部计划 vs 只扫今日到期的效率取舍（量级小，全量扫描可接受即可）。

**② rectifying 记录超期标记 + 通知**

- 扫描 status=rectifying 且 deadline < 今天 的记录。
- 标记超期：写 `hazard_notifications`（type="overdue"，user_id=整改责任人 rectification_user_id（若空则企业主），record_id 回填，message 含记录编号与「整改已超期」中文文案）+ audit log（留痕）。
- 防重：同 record 已存在 type="overdue" 通知则跳过（查询存在性，报告实现）。
- 若无 deadline（字典未配置）→ 不扫描（报告说明）。

**③ 任务提前提醒（due_at 前 2h）**

- 扫描 status in (pending, processing) 且 due_at - 2h <= now < due_at 的任务。
- 创建 `hazard_notifications`（type="upcoming"，user_id=任务责任人，message 含任务标题与期限「请在 YYYY-MM-DD HH:MM 前完成排查」）。
- **防重方案（需说明取舍）**：任务表仅有 `overdue_notified_at` 一个通知标记字段，语义是超期通知；为避免污染超期判断，建议二选一：
  - A（推荐）：给 `hazard_inspection_tasks` 幂等补列 `reminder_notified_at TIMESTAMPTZ NULL`（`ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 追加到 `db_migration_hazard_management.sql` + 模型补列），upcoming 提醒后写入，扫描条件 `reminder_notified_at IS NULL`；
  - B：查 notifications 存在性（enterprise/user/type=upcoming + record/task 关联），不用补列但依赖消息/关联查询。
  - 若选 A，同时把「超期扫描」对任务的 overdue 标记也实现（status→overdue + overdue_notified_at=now + 通知，规格 §6「扫描标记 + 上级通知」；注意任务超期与记录超期是两类，任务超期用 overdue_notified_at 防重）。报告完整说明。
