### 背景

`backend/app/services/onboarding_service.py` 的 risk_chemical 事件查询用 INNER JOIN RiskObject ON RiskEvent.object_id == RiskObject.id，但 `/units/{unit_id}/events` 创建的事件只写 unit_id、object_id 为空。只有 unit 级事件的企业会被误判为风险模块未完成。需补 unit 路径。

### 步骤 1：修复事件查询（覆盖 object 级 + unit 级）

先读 `backend/app/models/risk_management.py` 确认 RiskUnit 模型（应有 object_id 外键）。将 compute_completion 的事件查询改为：

```python
from app.models.risk_management import RiskEvent, RiskObject, RiskUnit

object_events = (await db.execute(
    select(RiskEvent).join(RiskObject, RiskEvent.object_id == RiskObject.id)
    .where(RiskObject.enterprise_id == enterprise_id)
)).scalars().all()
unit_events = (await db.execute(
    select(RiskEvent).join(RiskUnit, RiskEvent.unit_id == RiskUnit.id)
    .join(RiskObject, RiskUnit.object_id == RiskObject.id)
    .where(RiskObject.enterprise_id == enterprise_id)
)).scalars().all()
events = list(dict.fromkeys([*object_events, *unit_events]))
```

（事件要么挂 object 要么挂 unit，用 dict 去重防重复计数；后续判定逻辑不变。）
