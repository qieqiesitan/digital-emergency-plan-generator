### 背景

质量审查发现：`prompt_templates` 存在同 template_code 新旧双行（如 id 173 status='0' 旧文案 vs id 200 status='active' 新文案），`prompt_cache.py` 加载无排序、首个匹配可能取到旧行，导致 AI 提示词 resync 后运行时仍用旧文案。另有 `risk_notice_card_ai.py:88` 仍引用 GB 6441-1986，以及 `risk_notice_card_service.py:110` 应急模板查表未 normalize（与 match_signs 不对称）。

### 第 1 步：`backend\app\services\prompt_cache.py` 加确定性排序

修改 `_load_from_local_db` 的查询：加 `order_by`，active 优先、同状态按 id 降序（新行优先）。在文件顶部 import 区确认已引入所需函数（如 `from sqlalchemy import case`，若没有则加）：

```python
from sqlalchemy import case, select
```

查询改为：

```python
rows = (await db.execute(
    select(PromptTemplate)
    .where(PromptTemplate.status.in_(["active", "0"]))
    .order_by(
        case((PromptTemplate.status == "active", 0), else_=1),
        PromptTemplate.id.desc(),
    )
)).scalars().all()
```

这样缓存里 active 新行总在 status='0' 旧行之前，`get_report_system_prompt`/`get_report_section_prompt` 的首个匹配即新文案。

### 第 2 步：新建迁移 SQL `backend\db_migration_prompt_templates_cleanup.sql`

内容（幂等、非破坏：只把存在 active 同 code 的旧 status='0' 行下线为 'disabled'，不删除）：

```sql
-- 提示词模板旧行下线：同 template_code 存在 active 行时，将旧 status='0' 行置为 'disabled'
-- 幂等：重复执行无新影响
UPDATE prompt_templates old
SET status = 'disabled'
WHERE old.status = '0'
  AND EXISTS (
    SELECT 1 FROM prompt_templates act
    WHERE act.template_code = old.template_code
      AND act.status = 'active'
  );
```
