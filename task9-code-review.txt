## 问题

### 关键（建议合入前修复）

### 重要（建议本次或下次迭代修复）

1. **[建议修改] 保存成功后立即编辑存在被静默覆盖的竞态**（`RiskMappingWorkbenchPage.tsx:131-138` + `:44-46`）：`onSave` 用响应回填 store 后仍调用 `queryClient.invalidateQueries({ queryKey: ["risk-workbench", ...] })`，触发重新拉取；页面 `useEffect` 依赖 `data`，会在请求落地时无条件 `setSnapshot` 覆盖当前 store 并 `markSaved`。若用户在「保存成功提示 → 刷新落地」窗口内开始编辑（或连续保存），新改动会被静默丢弃且历史被清空。由于保存响应已包含权威数据，建议去掉 workbench 的 invalidate（保留 hierarchy/overview 的失效），或将覆盖逻辑改为仅在未改动时合并。

2. **[建议修改] 矩形/自由画笔拖出画布后松手，草稿可能残留**（`WorkbenchCanvas.tsx:163-196`）：`handleMouseUp` 只挂在 Stage 上，指针移出 Stage 后松开不会触发，`draftStart/draftEnd`（或 `draftPoints`）会残留为幽灵预览。建议在 Stage 外层补 window 级 mouseup 兜底，或对工具切换/离开画布做草稿清理。

3. **[建议修改] 保存按钮无 loading/防重**（`RiskMappingWorkbenchPage.tsx:74-78`）：`onSave` 为异步但按钮不显示 loading，连点可并发发送两个 batch-save（第二个大概率 SAVE_CONFLICT 误报「数据被他人修改」）。建议保存期间 `disabled` 或加 loading。

### 次要

4. **[仅供参考] 同毫秒新增文字存在 ID 碰撞风险**：属性面板 `addText` 仍用 `text-${Date.now()}`（`WorkbenchPropertiesPanel.tsx:49`），画布已改用带随机后缀的 `nextLocalId`，两个入口 ID 生成规则不一致；同毫秒连续添加会重复 key 且更新互相覆盖。建议面板也复用 `nextLocalId`。

5. **[仅供参考] 同分区多多边形可被拖散**：zone 的多边形是独立 `Line` 逐个拖动（`WorkbenchCanvas.tsx:289-318`），一个分区含多个区域时可单独位移造成形状撕裂；若预期是整区联动，建议后续按 zone 分组拖动。属设计取舍，需确认预期行为。

6. **[仅供参考] 「取消绘制」按钮只切工具、不清草稿**（`WorkbenchToolbar.tsx:69-71`）：绘制中切工具会残留未完成的草稿预览，与第 2 条同源，可一并处理。
