# 业务中台接入规范

> 版本：2.0.0 | 日期：2026-06-15
> 适用场景：外部业务系统接入业务中台，复用认证/权限/日志/工作流等通用能力
> 前言：接入全程约 15 分钟，业务中台零代码变更、零人工配置

---

## 一、接入前准备

在开始接入之前，请确认以下条件已满足：

| 序号 | 检查项 | 说明 |
|:--:|------|------|
| 1 | 网络可达 | 确认能访问中台网关地址（开发环境 `http://gateway:8088`） |
| 2 | Nacos 命名空间 | 确认目标环境命名空间：`dev`（开发）/ `staging`（预发）/ `prod`（生产） |
| 3 | 系统标识 (sysCode) | 提前拟定系统唯一标识，如 `crm`、`erp`、`oa`，仅含小写字母数字下划线，3-32 字符 |
| 4 | 系统名称 | 拟定系统中文显示名称，如「CRM 客户管理系统」 |
| 5 | 接入模式 | 确认接入模式：`backend` / `frontend` / `fullstack`（见第二章） |

---

## 二、三种接入模式

### 模式 A：仅后端接入（`sysType=backend`）

**适用场景**：有独立前端，只需复用中台的认证、权限、操作日志、工作流等后端能力。

**接入步骤（3 步）**：

```
外部系统后端 ──API 调用──▶ 业务中台网关 ──▶ Auth/System/Platform/AI
                                    │
外部系统前端（独立运行，不嵌入中台）   └── JWT 认证 + 权限校验 + 日志上报
```

**第 1 步：自注册**

```bash
curl -X POST http://gateway:8088/api/registry/system \
  -H "Content-Type: application/json" \
  -d '{
    "sysCode": "crm",
    "sysName": "CRM客户管理系统",
    "sysType": "backend"
  }'
```

**第 2 步：后端集成**（详见[步骤 2：后端集成](#步骤-2后端集成如适用)）

- 添加 `yewuzhongtai-client-starter` 依赖
- 配置 `application.yml` 中 `ywt.sys-code` 和 `ywt.gateway-url`
- 使用 `@YwtLog` 注解上报操作日志
- 通过 `UserContext` / `PermissionClient` 获取用户和权限

**第 3 步：验证接入**（详见[步骤 4：验证接入](#步骤-4验证接入)）

---

### 模式 B：仅前端接入（`sysType=frontend`）

**适用场景**：有独立后端，只需前端嵌入中台主应用，复用中台用户体系。

**接入步骤（3 步）**：

```
业务中台主应用（Vue 3）
│
├── 中台自身页面（系统管理、AI控制台...）
│
└── qiankun 加载 ──▶ 外部系统前端（Vue 3 子应用）
                       │
                       └── API 调用 ──▶ 外部系统后端（Token 由中台注入）
```

**第 1 步：自注册**

```bash
curl -X POST http://gateway:8088/api/registry/system \
  -H "Content-Type: application/json" \
  -d '{
    "sysCode": "crm-ui",
    "sysName": "CRM客户管理",
    "sysType": "frontend",
    "subAppEntry": "http://crm.company.com/entry.js"
  }'
```

**第 2 步：前端集成**（详见[步骤 3：前端集成](#步骤-3前端集成如适用)）

- 实现 qiankun 生命周期（`bootstrap` / `mount` / `unmount`）
- 独立构建部署到 nginx
- 中台侧栏自动出现入口

**第 3 步：验证接入**（详见[步骤 4：验证接入](#步骤-4验证接入)）

---

### 模式 C：全栈接入（`sysType=fullstack`）

**适用场景**：完整接入，后端复用中台能力 + 前端嵌入中台主应用。

**接入步骤（4 步）**：

```
外部 CRM 系统
├── 后端 (Spring Boot)         前端 (Vue 3)
│   ├── ywt-client-starter     ├── qiankun 生命周期
│   ├── @YwtLog 注解           ├── props.token（中台 JWT）
│   ├── Token 自动续期         └── 独立部署
│   └── 权限查询
│
▼ 通过网关统一入口
┌──────────────────────────────────────────┐
│              业务中台网关 (8080)           │
│  JWT 认证 | 动态路由 | 限流熔断 | CORS    │
├──────────┬──────────┬──────────┬─────────┤
│  Auth    │  System  │ Platform │   AI    │
│  8100    │  8200    │  8300    │  8400   │
├──────────┴──────────┴──────────┴─────────┤
│  PostgreSQL | Redis | Nacos | RabbitMQ    │
└──────────────────────────────────────────┘
```

**第 1 步：自注册**

```bash
curl -X POST http://gateway:8088/api/registry/system \
  -H "Content-Type: application/json" \
  -d '{
    "sysCode": "crm",
    "sysName": "CRM客户管理系统",
    "sysType": "fullstack",
    "routePrefix": "/crm",
    "subAppEntry": "http://crm.company.com/entry.js",
    "adminUsername": "crm_admin",
    "adminPassword": "crm123"
  }'
```

**第 2 步：后端集成**（同模式 A）

**第 3 步：前端集成**（同模式 B）

**第 4 步：验证接入**（详见[步骤 4：验证接入](#步骤-4验证接入)）

## 三、通用接入流程

### 步骤 1：系统自注册

调用自注册 API，一次性自动完成以下全部工作：

| 自动完成项 | 说明 |
|-----------|------|
| 系统标识注册 | `sys_system` 表写入记录 |
| 生成 apiKey | 32 位 UUID，仅返回一次 |
| 网关路由追加 | Nacos 配置 `yewuzhongtai-gateway.yml` 热刷新生效 |
| 菜单节点创建 | `sys_menu` 表创建对应菜单 |
| 系统管理员角色 | `sys_role` 表创建管理员角色 |
| 管理员账号创建 | `sys_user` 表创建管理员账号（若提供了 adminUsername） |

**API：POST /api/registry/system**

认证：无需认证（公开接口）

| 字段 | 类型 | 必填 | 说明 |
|------|------|:--:|------|
| `sysCode` | String | ✅ | 系统唯一标识，如 `crm`，仅含小写字母数字下划线，3-32 字符 |
| `sysName` | String | ✅ | 系统显示名称，如「CRM客户管理系统」 |
| `sysType` | String | ✅ | 接入模式：`backend` / `frontend` / `fullstack` |
| `routePrefix` | String | - | 网关路由前缀，如 `/crm`。`backend` / `fullstack` 建议填写 |
| `subAppEntry` | String | - | 微前端入口 URL。`frontend` / `fullstack` 必填 |
| `adminUsername` | String | - | 系统管理员用户名，不填则不自动创建用户 |
| `adminPassword` | String | - | 系统管理员密码，不填则随机生成 12 位密码并在响应中返回 |

**请求示例（全栈模式）**：

```bash
curl -X POST http://gateway:8088/api/registry/system \
  -H "Content-Type: application/json" \
  -d '{
    "sysCode": "crm",
    "sysName": "CRM客户管理系统",
    "sysType": "fullstack",
    "routePrefix": "/crm",
    "subAppEntry": "http://crm.company.com/entry.js",
    "adminUsername": "crm_admin",
    "adminPassword": "Admin@123"
  }'
```

**成功响应**：

```json
{
  "code": 200,
  "data": {
    "sysCode": "crm",
    "apiKey": "a1b2c3d4e5f6789012345678abcdef01",
    "message": "系统注册成功",
    "apiDocsUrl": "http://gateway:8088/docs/接入规范.md"
  }
}
```

**失败响应**：

```json
{
  "code": 500,
  "msg": "系统标识 crm 已存在"
}
```

> ⚠️ **重要**：`apiKey` 仅返回一次，请妥善保存。丢失后需联系中台管理员重置。

**查询注册状态**：

```bash
curl http://gateway:8088/api/registry/system/crm \
  -H "X-Api-Key: a1b2c3d4e5f6789012345678abcdef01"
```

### 步骤 2：后端集成（如适用）

> 适用模式：`backend` / `fullstack`

#### 2.1 添加 Maven 依赖

```xml
<dependency>
    <groupId>com.yewuzhongtai</groupId>
    <artifactId>yewuzhongtai-client-starter</artifactId>
    <version>1.0.0-SNAPSHOT</version>
</dependency>
```

#### 2.2 配置 application.yml

```yaml
ywt:
  sys-code: crm                          # 与注册时的 sysCode 一致
  gateway-url: http://ywt-gateway:8088   # 中台网关地址
```

#### 2.3 操作日志上报

使用 `@YwtLog` 注解自动上报操作日志到中台：

```java
@RestController
@RequestMapping("/api/customers")
public class CustomerController {

    @YwtLog(title = "新增客户", businessType = "INSERT")
    @PostMapping
    public Result<Customer> add(@RequestBody Customer customer) {
        // 业务逻辑
        return Result.ok(customerService.save(customer));
    }

    @YwtLog(title = "更新客户", businessType = "UPDATE")
    @PutMapping("/{id}")
    public Result<Customer> update(@PathVariable Long id, @RequestBody Customer customer) {
        return Result.ok(customerService.updateById(id, customer));
    }

    @YwtLog(title = "删除客户", businessType = "DELETE")
    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Long id) {
        customerService.removeById(id);
        return Result.ok();
    }
}
```

操作日志自动包含：操作人、所属系统、操作时间、请求参数、响应结果。

#### 2.4 获取当前用户

```java
import com.yewuzhongtai.client.context.UserContext;

// 获取当前登录用户 ID
Long userId = UserContext.getCurrentUserId();

// 获取当前用户名
String username = UserContext.getCurrentUsername();

// 获取当前用户所属系统
String sysCode = UserContext.getCurrentSysCode();
```

`UserContext` 从网关透传的 JWT Token 中自动解析，无需额外配置。

#### 2.5 查询用户权限

```java
import com.yewuzhongtai.client.permission.PermissionClient;

@Autowired
private PermissionClient permissionClient;

// 判断当前用户是否有某权限
boolean hasPermission = permissionClient.hasPermission("crm:customer:add");

// 获取当前用户所有权限列表
Set<String> permissions = permissionClient.getPermissions();

// 获取当前用户角色列表
List<String> roles = permissionClient.getRoles();
```

#### 2.6 Token 自动续期

SDK 内置 Token 自动续期机制，无需额外代码：

```java
// Token 过期时自动刷新，业务代码无需感知
@Autowired
private RestTemplate restTemplate;  // 已集成续期拦截器

// 正常调用即可
String result = restTemplate.getForObject(
    "http://gateway:8088/crm/api/data", String.class);
```

工作流程：`请求 → 401 → 自动用 refreshToken 换新 → 重试原请求 → 返回结果`

### 步骤 3：前端集成（如适用）

> 适用模式：`frontend` / `fullstack`

#### 3.1 子应用入口（entry.js）

```javascript
// entry.js — 子应用入口文件
// 部署到独立 nginx，如 http://crm.company.com/

let app = null;

/**
 * 渲染函数 — 同时支持 qiankun 加载和独立运行
 */
function render(props = {}) {
  const { container } = props;
  // 使用 Vue 3 挂载
  app = createApp(App)
    .use(router)
    .use(store);
  app.mount(container ? container.querySelector('#app') : '#app');
}

// ── qiankun 生命周期 ──

export async function bootstrap() {
  console.log('[CRM] 子应用初始化');
}

export async function mount(props) {
  console.log('[CRM] 子应用挂载', props);
  // props 包含中台传入的数据：
  //   props.token    — 中台 JWT Token（用于调后端 API）
  //   props.username — 当前登录用户名
  //   props.sysCode  — 系统标识
  //   props.userInfo — 用户信息对象（含昵称、角色等）
  render(props);
}

export async function unmount() {
  console.log('[CRM] 子应用卸载');
  app?.unmount();
  app = null;
}

// ── 独立运行 ──
if (!window.__POWERED_BY_QIANKUN__) {
  render({});
}
```

#### 3.2 Vue 3 子应用 webpack 配置

```javascript
// vue.config.js
module.exports = {
  publicPath: '//crm.company.com',
  outputDir: 'dist',
  devServer: {
    port: 9001,
    headers: {
      'Access-Control-Allow-Origin': '*'   // 允许中台跨域加载
    }
  },
  configureWebpack: {
    output: {
      library: 'crm',
      libraryTarget: 'umd',                 // 必须 UMD 格式
      globalObject: 'window'
    }
  }
};
```

#### 3.3 独立构建部署

```bash
# 构建
pnpm build

# 部署到 nginx
# dist/ 目录内容复制到 nginx html 目录
# nginx 需配置 CORS 头
```

Nginx 配置参考：

```nginx
server {
    listen 80;
    server_name crm.company.com;

    location / {
        root /usr/share/nginx/html;
        index index.html;
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods 'GET, POST, OPTIONS';
        add_header Access-Control-Allow-Headers '*';
    }
}
```

#### 3.4 效果

部署完成后，中台用户登录 → 侧栏自动出现「CRM客户管理系统」入口 → 点击即用，无需额外配置。

### 步骤 4：验证接入

按顺序验证以下项目：

#### 4.1 验证路由可达

```bash
# 如果注册时填写了 routePrefix，网关已自动追加路由
curl http://gateway:8088/crm/api/health

# 预期：返回 200 或后端服务的健康检查结果
```

#### 4.2 验证 Token 鉴权

```bash
# 无 Token 访问 → 应返回 401
curl http://gateway:8088/crm/api/customers

# 预期：
# {"code": 401, "msg": "未登录或 Token 已过期"}

# 带 Token 访问 → 应返回正常数据
curl http://gateway:8088/crm/api/customers \
  -H "Authorization: Bearer <accessToken>"

# 预期：200 + 业务数据
```

#### 4.3 验证日志上报

1. 在后端方法上加 `@YwtLog` 注解
2. 调用该接口一次
3. 登录中台 → 系统管理 → 操作日志 → 按「所属系统」筛选
4. 预期：能看到刚才的操作日志记录

#### 4.4 验证前端嵌入（如适用）

1. 登录中台主应用
2. 查看侧栏是否出现新系统的入口
3. 点击入口，确认子应用正常加载
4. 验证子应用中 API 调用正常（Token 已自动注入）

## 四、数据隔离规范

### 4.1 隔离原则

所有核心业务表按 `sys_code` 字段隔离，确保各系统数据互相不可见。

### 4.2 权限模型

| 角色 | 可见范围 | 可注册新系统 |
|------|---------|:--:|
| 超级管理员（`role_key=admin`） | 全部系统的数据 | ✅ |
| 系统管理员（如 `crm_admin`） | 仅本系统数据 | ❌ |
| 普通用户 | 仅本系统数据 | ❌ |

### 4.3 涉及隔离的表

| 表名 | 隔离方式 | 说明 |
|------|---------|------|
| `sys_user` | `sys_code` 字段 | 用户归属系统 |
| `sys_role` | `sys_code` 字段 | 角色归属系统 |
| `sys_menu` | `sys_code` 字段 | 菜单归属系统 |
| `sys_dept` | `sys_code` 字段 | 部门归属系统 |
| `sys_dict_type` | `sys_code` 字段 | 字典归属系统 |
| `sys_oper_log` | `sys_code` 字段 | 操作日志来源系统 |
| `sys_login_log` | `sys_code` 字段 | 登录日志来源系统 |

### 4.4 后端查询拦截

Service 层自动根据当前用户角色注入 `sys_code` 过滤条件：

```java
// 系统管理员登录 → 自动注入 WHERE sys_code = 'crm'
// 超级管理员登录 → 不注入过滤（查全部）
List<SysUser> users = userService.list();

// 等价于：
// 系统管理员：SELECT * FROM sys_user WHERE sys_code = 'crm'
// 超级管理员：SELECT * FROM sys_user
```

外部业务系统调用中台 API 时使用自己的数据表，不与中台核心表混淆。

## 五、安全规范

### 5.1 apiKey 管理

| 规则 | 说明 |
|------|------|
| 保密存储 | `apiKey` 不得提交到代码仓库，建议使用环境变量或密钥管理服务 |
| 丢失处理 | 联系中台管理员重置，重置后旧 key 立即失效 |
| 轮换周期 | 建议每 90 天更换一次（联系管理员操作） |
| 传输方式 | 仅通过 HTTPS 传输（生产环境必须启用 TLS） |

### 5.2 Token 有效期

| Token 类型 | 有效期 | 说明 |
|-----------|--------|------|
| `accessToken` | 30 分钟 | 过期后前端自动用 refreshToken 刷新 |
| `refreshToken` | 7 天 | 过期后需重新登录 |

### 5.3 敏感操作二次确认

以下操作需要管理员二次确认：

- 系统下线（停用系统）
- 删除核心数据
- 修改 apiKey
- 修改系统管理员权限

### 5.4 安全建议

- 生产环境 Nacos 必须启用认证
- 数据库密码定期更换
- API 调用记录在操作日志中，可用于审计
- 外部系统后端建议加 IP 白名单限制

## 六、系统下线规范

### 6.1 停用（软下线）

| 步骤 | 操作 | 效果 |
|:--:|------|------|
| 1 | Nacos 删除路由配置 | 网关不再转发请求 |
| 2 | 菜单管理页面隐藏该系统菜单 | 前端入口消失 |
| 3 | `sys_system` 表 `status` 设为 `1`（停用） | 系统侧栏不再显示 |

### 6.2 彻底清理

| 步骤 | 操作 |
|:--:|------|
| 1 | 停止该系统容器 |
| 2 | Redis 按 `{sysCode}:*` 前缀清理缓存 |
| 3 | 数据库 Schema 归档后删除 |
| 4 | Nacos 清理相关配置 |

## 八、常见问题

**Q: 注册后多久生效？**

A: 数据库写入即时生效；网关路由需等 Nacos 刷新（约 5-10 秒）。注册成功后可在 30 秒内通过网关访问新系统路由。

**Q: 非 Java 系统如何接入？**

A: 可直接通过 HTTP 调中台 API（认证用 JWT Token），但不能使用 `@YwtLog`、`UserContext` 等 SDK 注解和工具类。建议至少引入一个适配层来处理 Token 续期和日志上报。Go/Python/Node.js 等其他语言的 SDK 未来会逐步提供。

**Q: apiKey 丢失了怎么办？**

A: 联系中台管理员重置。重置后旧 key 立即失效，新 key 重新返回一次。未来会增加自助重置功能。

**Q: 如何查看操作日志？**

A: 登录中台 → 系统管理 → 操作日志，按「所属系统」筛选即可查看。也可以通过 API 查询：

```bash
curl http://gateway:8088/system/oper-log/list?sysCode=crm \
  -H "Authorization: Bearer <accessToken>"
```

**Q: 多环境怎么隔离？**

A: 不同环境使用不同 Nacos namespace。在 `docker-compose.yml` 的 `.env` 中设置 `NACOS_NAMESPACE` 区分 dev/staging/prod。各环境注册独立的 apiKey，互不影响。

**Q: 接入后需要手动配置网关路由吗？**

A: 不需要。自注册 API 会自动通过 Nacos OpenAPI 追加路由到 `yewuzhongtai-gateway.yml`，网关实时热刷新，全程零手动。

**Q: 子应用加载失败怎么办？**

A: 中台前端有降级 UI 处理：如果子应用入口 (`subAppEntry`) 不可达，显示友好错误提示和重试按钮，不影响中台其他页面正常运行。

**Q: 可以注册多个系统吗？**

A: 可以。每个系统使用不同的 `sysCode`，各自拥有独立的 apiKey、菜单、角色和用户。同一个团队可以注册多个系统。

**Q: 接入后中台升级会影响外部系统吗？**

A: 接入规范向下兼容。中台升级时 SDK 版本兼容性由 `GET /api/registry/version` 接口校验，SDK 启动时自动检测并提示。网关路由、API 接口保持兼容。
