# 业务中台子应用开发规范

> 版本: 1.0 | 更新: 2026-06-15 | 适用: qiankun ^2.10.16 + Vue 3 + Element Plus + TypeScript + Vite

## 一、概述

业务中台基于 **qiankun ^2.10.16** 微前端框架，主应用（`main-app`）通过 `SubAppContainer.vue` 动态注册和加载子应用。核心流程：

1. 主应用从菜单 API (`/system/menu/list?menuType=M`) 获取微前端菜单项
2. 调用 `registerMicroApps()` 注册子应用，传入 props：`{ token, username, nickname, sysCode }`
3. 子应用导出的 `mount` 生命周期接收 props，提取 Token 和用户信息
4. 子应用独立开发、独立构建、独立部署，通过 URL 接入主应用

### 主应用侧关键实现 (SubAppContainer.vue)

```typescript
// 参考: yewuzhongtai-ui/packages/main-app/src/views/micro/SubAppContainer.vue
registerMicroApps(apps, {
  beforeLoad: [async () => { loading.value = true }],
  afterMount: [async () => { loading.value = false }],
})

start({ sandbox: { experimentalStyleIsolation: true } })
```

主应用向子应用注入的 props 结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| `token` | `string` | JWT accessToken，用于 API 鉴权 |
| `username` | `string` | 当前登录用户名 |
| `nickname` | `string` | 用户昵称 |
| `sysCode` | `string` | 子系统标识（如 `crm`、`erp`） |

## 二、子应用创建

### 2.1 项目初始化

```bash
pnpm create vite my-sub-app --template vue-ts
cd my-sub-app
pnpm add qiankun
pnpm add axios element-plus
```

### 2.2 入口文件

子应用必须导出三个 qiankun 生命周期函数：`bootstrap`、`mount`、`unmount`。

```javascript
// src/entry.js
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'

let app = null
let instance = null

/**
 * 接收主应用传入的 props 并缓存到全局
 * props 结构: { token, username, nickname, sysCode, container }
 */
function render(props = {}) {
  const { container } = props

  // 将主应用注入的能力挂到全局，方便各模块使用
  window.__MIDDLE_PLATFORM_PROPS__ = props

  app = createApp(App)
  app.use(router)
  instance = app.mount(
    container ? container.querySelector('#app') : '#app'
  )
}

// ========== qiankun 生命周期 ==========

export async function bootstrap() {
  console.log('[子应用] bootstrap')
}

export async function mount(props) {
  console.log('[子应用] mount', props)
  render(props)
}

export async function unmount() {
  console.log('[子应用] unmount')
  instance = null
  app?.unmount()
  app = null
}

// ========== 独立运行（非 qiankun 环境） ==========
if (!window.__POWERED_BY_QIANKUN__) {
  render()
}
```

### 2.3 Vite 配置

```typescript
// vite.config.ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import qiankun from 'vite-plugin-qiankun'

export default defineConfig({
  plugins: [
    vue(),
    // 第一个参数为子应用名称，需与主应用注册时的 name 一致
    qiankun('my-sub-app', { useDevMode: true })
  ],
  server: {
    port: 3002,
    cors: true,
    origin: 'http://localhost:3002',
    // 子应用资源路径前缀，避免与主应用路由冲突
    headers: {
      'Access-Control-Allow-Origin': '*',
    }
  },
  // 构建时资源路径设为相对路径
  base: '/',
})
```

## 三、中台能力注入

### 3.1 获取注入参数

```typescript
// src/utils/platform.ts

interface PlatformProps {
  token: string
  username: string
  nickname: string
  sysCode: string
  container?: HTMLElement
  onGlobalStateChange?: Function
  setGlobalState?: Function
  offGlobalStateChange?: Function
}

/** 获取主应用注入的 props（挂载时写入 window） */
export function getPlatformProps(): PlatformProps {
  return (window as any).__MIDDLE_PLATFORM_PROPS__ || {}
}

export function getToken(): string {
  return getPlatformProps().token || ''
}

export function getUsername(): string {
  return getPlatformProps().username || ''
}

export function getSysCode(): string {
  return getPlatformProps().sysCode || ''
}
```

### 3.2 API 请求封装

子应用调用中台 API 时**必须通过主应用网关**（同域，走 Nginx 反代），并在请求头携带 Token：

```typescript
// src/utils/request.ts
import axios from 'axios'
import { getToken } from './platform'
import { ElMessage } from 'element-plus'

const request = axios.create({
  baseURL: '/',       // 与主应用同域，走网关
  timeout: 30000,
})

// 请求拦截器：自动注入 Token
request.interceptors.request.use(config => {
  const token = getToken()
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 响应拦截器：统一错误处理
request.interceptors.response.use(
  response => {
    const { code, msg, data } = response.data
    if (code === 200) {
      return data
    }
    ElMessage.error(msg || '请求失败')
    return Promise.reject(new Error(msg))
  },
  error => {
    if (error.response?.status === 401) {
      ElMessage.error('登录过期，请刷新页面')
    }
    return Promise.reject(error)
  }
)

export default request
```

### 3.3 获取菜单权限

```typescript
// src/api/menu.ts
import request from '@/utils/request'

/** 获取当前子系统的菜单树 */
export function getMenuTree() {
  return request.get('/system/menu/list', {
    params: { sysCode: getSysCode() }
  })
}
```

### 3.4 调用已有中台 API 示例

```typescript
import request from '@/utils/request'

// 用户列表
request.get('/system/user/list', { params: { pageNum: 1, pageSize: 10 } })

// 字典查询
request.get('/system/dict/data/type/{dictType}')

// 文件上传
```

## 四、路由配置

### 4.1 子应用路由

子应用路由的 **path 必须与中台菜单配置中的路由路径一致**，否则菜单点击后无法正确匹配。

```typescript
// src/router/index.ts
import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  {
    path: '/',
    redirect: '/dashboard'
  },
  {
    path: '/dashboard',
    name: 'Dashboard',
    component: () => import('@/views/Dashboard.vue'),
    meta: { title: '工作台' }
  },
  {
    path: '/customer',
    name: 'CustomerList',
    component: () => import('@/views/CustomerList.vue'),
    meta: { title: '客户列表' }
  },
  {
    path: '/customer/:id',
    name: 'CustomerDetail',
    component: () => import('@/views/CustomerDetail.vue'),
    meta: { title: '客户详情' }
  },
]

const router = createRouter({
  // qiankun 环境下使用子应用自己的 base
  history: createWebHistory(
    (window as any).__POWERED_BY_QIANKUN__ ? '/crm' : '/'
  ),
  routes,
})

export default router
```

### 4.2 路由与菜单的对应关系

| 中台菜单 path | 子应用路由 path | 说明 |
|-------------|---------------|------|
| `/crm/dashboard` | `/dashboard` | 中台配置完整路径，子应用内部用相对路径 |
| `/crm/customer` | `/customer` | 同上 |
| `/crm/customer/:id` | `/customer/:id` | 动态路由参数保持一致 |

> **注意**: 中台菜单配置时，`routePrefix` 设为 `/crm`，菜单项的 `path` 设为 `/crm/dashboard`。子应用内部路由只需 `/dashboard`，qiankun 会在激活时自动处理路径匹配。

## 五、构建与部署

### 5.1 构建产物

```bash
pnpm build
```

Vite 默认输出到 `dist/`，包含 `index.html` 及 `assets/` 目录。

### 5.2 Nginx 部署

```nginx
server {
    listen 3002;
    server_name crm.company.com;

    root /usr/share/nginx/html;
    index index.html;

    # SPA 回退：所有路由返回 index.html
    location / {
        try_files $uri $uri/ /index.html;

        # 跨域支持：qiankun 通过 fetch 拉取子应用资源
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods 'GET, OPTIONS';
        add_header Cache-Control 'no-cache';
    }

    # 静态资源长缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control 'public, immutable';
        add_header Access-Control-Allow-Origin *;
    }
}
```

### 5.3 Dockerfile（可选）

```dockerfile
FROM nginx:alpine
COPY dist/ /usr/share/nginx/html/
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 3002
```

### 5.4 在中台注册

通过中台「系统管理 → 菜单管理」或自注册 API 注册子系统：

```json
{
  "sysCode": "crm",
  "sysName": "CRM系统",
  "sysType": "fullstack",
  "routePrefix": "/crm",
  "subAppEntry": "http://crm.company.com:3002/entry.js",
  "menus": [
    { "name": "工作台", "path": "/crm/dashboard", "menuType": "M" },
    { "name": "客户管理", "path": "/crm/customer", "menuType": "M" }
  ]
}
```

注册后，中台系统侧栏自动出现对应菜单，点击后 `SubAppContainer.vue` 加载子应用。

## 六、样式规范

| 规则 | 说明 |
|------|------|
| **组件库** | 统一使用 Element Plus，保持与主应用视觉一致 |
| **样式隔离** | 主应用已启用 `experimentalStyleIsolation: true`，子应用无需额外配置 |
| **全局样式** | 避免写 `body {}`、`html {}` 等全局选择器，防止污染主应用 |
| **CSS Modules** | 推荐使用 `<style scoped>` 或 CSS Modules，将样式限制在组件内 |
| **主题变量** | 使用 Element Plus CSS 变量覆盖主题色，不要硬编码颜色值 |

**推荐做法**：

```vue
<template>
  <div class="customer-page">
    <el-card class="search-card">
      <!-- ... -->
    </el-card>
  </div>
</template>

<style scoped>
.customer-page {
  padding: 16px;
}
.search-card {
  margin-bottom: 16px;
}
</style>
```

## 七、调试与排错

### 7.1 本地开发

**方式一：子应用独立运行**

```bash
pnpm dev
# 访问 http://localhost:3002
```

独立运行时 `window.__POWERED_BY_QIANKUN__` 为 `undefined`，`entry.js` 自动调用 `render()`。

**方式二：集成调试**

1. 启动主应用和子应用
2. 在 Nacos 或数据库中，将对应菜单的 `component` 字段设为 `http://localhost:3002/entry.js`
3. 从主应用侧栏点击进入子应用

### 7.2 常见错误

| 错误现象 | 可能原因 | 排查步骤 |
|---------|---------|---------|
| 子应用加载失败 / 白屏 | entry URL 不可达 | ① 浏览器直接访问 entry URL 看是否返回 JS ② 检查子应用是否启动 ③ 检查 CORS 头 |
| Token 未注入 / API 401 | qiankun props 未传递 | ① 打印 `mount` 函数的 props 参数 ② 检查 `getToken()` 返回值 |
| 路由 404（刷新后） | Nginx 未配置 try_files | 检查 `nginx.conf` 是否有 `try_files $uri $uri/ /index.html` |
| 样式错乱 | CSS 全局污染 | ① 确认主应用已开启 `experimentalStyleIsolation` ② 子应用改用 `<style scoped>` |
| 子应用资源 404 | publicPath 不正确 | 检查 `vite.config.ts` 的 `base` 和 server `origin` 配置 |
| `regeneratorRuntime is not defined` | Vite 未 polyfill | 安装 `regenerator-runtime` 并在 entry.js 顶部 `import 'regenerator-runtime/runtime'` |

### 7.3 调试技巧

```javascript
// 在子应用 entry.js 的 mount 中添加调试日志
export async function mount(props) {
  console.log('[子应用] 收到 props:', {
    token: props.token ? '***' + props.token.slice(-8) : '空',
    username: props.username,
    sysCode: props.sysCode,
    hasContainer: !!props.container,
  })
  render(props)
}
```

## 八、检查清单

子应用接入中台前，逐项确认：

- [ ] `entry.js` 导出 `bootstrap` / `mount` / `unmount` 三个生命周期
- [ ] `vite.config.ts` 配置 `qiankun()` 插件和 `cors: true`
- [ ] API 请求自动携带 `Authorization: Bearer <token>`
- [ ] Token 从 `mount(props)` 的 `props.token` 获取，不自己存 localStorage
- [ ] 路由 path 与中台菜单配置一致
- [ ] Nginx 配置 `try_files` 和 CORS 头
- [ ] 不使用全局样式（`body`、`html` 选择器）
- [ ] 独立运行 (`pnpm dev`) 和集成运行均正常
- [ ] 构建产物 `dist/` 可正常部署
- [ ] 在中台菜单管理注册子应用入口 URL
