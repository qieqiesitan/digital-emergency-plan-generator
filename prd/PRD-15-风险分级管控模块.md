 # PRD-15：风险分级管控模块（第 1 段：模块概述 + 数据模型）
 
 > **版本**：2.0 | **创建日期**：2026-07-29 | **依赖**：PRD-00, PRD-01, PRD-02, PRD-11
 
 ---
 
 ## 1. 模块概述
 
 ### 1.1 法规背景
 
 根据《中华人民共和国安全生产法》第二十一条，生产经营单位的主要负责人对本单位安全生产工作负有下列职责：（五）组织建立并落实安全风险分级管控和隐患排查治理双重预防工作机制，督促、检查本单位的安全生产工作，及时消除生产安全事故隐患。
 
 根据《国务院安委会办公室关于实施遏制重特大事故工作指南构建双重预防机制的意见》（安委办〔2016〕11 号）：
 
 > 企业要组织开展安全风险辨识、评估和分级管控工作。要依据有关标准规范，采用适用的风险评估方法，对辨识出的风险进行评估分级，确定风险等级。针对不同等级的风险，从组织、制度、技术、应急等方面采取有针对性的管控措施。
 
 现行系统（PRD-02 §2.3 风险源管理 和 PRD-11 风险评估报告）采用扁平化的单表 `risk_sources` 存储全部风险数据，一个字段同时承担"是什么设备、在什么位置、有什么风险"三个维度的信息。这导致：
 
 1. **无法体现层级管控逻辑**：法规要求的"分区→对象→单元→事件→措施"五级管控体系无法用一张 flat 表表达
 2. **风险评估方法硬编码**：仅支持一种简化的 3×3 矩阵（高/中/低），不支持 LS 矩阵（5 级）、LEC 评价法（L×E×C）等行业标准方法，更无法让用户自定义
 3. **无 AI 辅助能力**：完全依赖用户手动逐条录入，对于有上百个风险事件的中大型企业，录入工作量和专业门槛都很高
 4. **无可视化总览**：没有厂区平面图热区、风险矩阵热力图、统计分析等直观的风险概览手段
 
 本模块对风险管理子系统进行全面重构，补齐上述全部缺失。
 
 ### 1.2 模块定义
 
 风险分级管控模块是企业安全管理数据的**核心入口**。用户通过结构化的五层层级表单，从宏观（分区）到微观（具体管控措施和检查项目）逐级录入。系统根据用户选定的风险评估方法，在事件录入时自动计算风险等级。模块支持三种工作模式以适应不同场景：
 
 | 模式 | 说明 | 适用场景 | AI 参与度 |
 |------|------|----------|:---:|
 | **逐层手动录入** | 用户在各层表单中手动填写全部字段，每层可选点击「AI 建议」按钮获得 AI 辅助 | 精细化管理、数据已有明确来源 | 可选辅助 |
 | **AI 辅助录入** | 进入表单时 AI 自动预填字段（以淡蓝色背景标注），用户逐字段确认或修改 | 快速填充、减少重复劳动 | 中度参与 |
 | **一键智能导引** | 用户在文本框中自然语言描述一个区域（如"储罐区有3个原油储罐…"），AI 生成完整层级结构供审核确认 | 新建企业、新建大区域 | 高度参与 |
 
 核心设计理念：**AI 始终扮演"建议者"角色**，其输出在用户明确确认前不会写入数据库。每个 AI 建议都伴随「采纳」「修改」「忽略」三种操作选择。AI 服务不可用时，所有手动录入功能正常工作，不受任何影响。

 ## 2. 数据模型
 
 ### 2.1 实体关系与设计原则
 
 ```
 enterprises (1)──(N) risk_zones (1)──(N) risk_objects (1)──(N) risk_units (1)──(N) risk_events (1)──(N) risk_measures
      │                                │                          │
      │ (对象可脱离分区独立存在)        │ (事件可直接挂在对象下)    │
      │                                │ (与挂在单元下互斥)       │
      │                                │                          │
      └─ risk_assessment_methods (N) ──┘ (企业可拥有多个自定义方法)
 ```
 
 **设计原则**：
 
 1. **每层独立表，外键级联**：分区→对象→单元→事件→措施，每层一张表，通过外键关联。删除上层数据自动级联删除下层数据，保证数据一致性
 2. **事件双挂载**：风险事件可以挂在单元下（`risk_events.unit_id`）或直接挂在对象下（`risk_events.object_id`），二者互斥（数据库 CHECK 约束保证）。挂在对象下适用于简单场景（如"消防泵房"没有子单元，直接关联"设备故障"事件）
 3. **方法配置 JSONB 化**：评估方法的所有参数、阈值、描述文本全部存储在 `risk_assessment_methods.config` 的 JSONB 字段中，后端计算引擎从 JSONB 读取，前端可视化编辑器直接操作 JSONB。零代码硬编码
 4. **方法查询优先级**：创建事件时，先查企业级方法（`enterprise_id` 非空），未命中则回退系统级方法（`enterprise_id IS NULL`）。企业可通过复制系统方法创建自定义版本
 5. **坐标百分比制**：`risk_zones.floor_plan_polygon` 和 `risk_objects.location_x/y` 均使用百分比坐标（0~100），与图片实际像素尺寸解耦，适配不同分辨率
 
 ### 2.2 风险评估方法配置表 — risk_assessment_methods
 
 ```sql
 CREATE TABLE risk_assessment_methods (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     enterprise_id UUID REFERENCES enterprises(id) ON DELETE CASCADE,
     method_type VARCHAR(20) NOT NULL
         CHECK (method_type IN ('LS', 'LEC', 'COAL_LS', 'DIRECT')),
     name VARCHAR(100) NOT NULL,
     description TEXT DEFAULT '',
     config JSONB NOT NULL DEFAULT '{}'::jsonb,
     is_active BOOLEAN NOT NULL DEFAULT true,
     is_system BOOLEAN NOT NULL DEFAULT false,
     created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
     updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
 );
 
 CREATE INDEX idx_ram_enterprise ON risk_assessment_methods(enterprise_id);
 CREATE INDEX idx_ram_type_active ON risk_assessment_methods(method_type, is_active)
     WHERE is_active = true;
 ```

 **LEC 评价法的 config 结构差异**：
 
 LEC 方法的 `parameters` 数组包含三个参数（l/e/c），每个参数使用不同的分值体系：
 - L（事故发生的可能性）：`range: [0.1, 10]`，7 个等级（0.1/0.2/0.5/1/3/6/10），对应"实际不可能"到"完全可以预料"
 - E（人员暴露于危险环境的频繁程度）：`range: [0.5, 10]`，6 个等级（0.5/1/2/3/6/10），对应"非常罕见"到"连续暴露"
 - C（发生事故产生的后果）：`range: [1, 100]`，6 个等级（1/3/7/15/40/100），对应"引人注意"到"大灾难"
 
 `formula` 为 "D = L × E × C"，`risk_thresholds` 的 min/max 范围相应调整（重大≥320、较大 160-319、一般 70-159、低<70）。
 
 **直接判定法（DIRECT）**的 config：无 `parameters` 数组，无 `formula`，`risk_thresholds` 仅用于枚举可用等级名称。用户直接选择等级，不计算分值。
 
 ### 2.3 风险分区表 — risk_zones
 
 ```sql
 CREATE TABLE risk_zones (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     enterprise_id UUID NOT NULL REFERENCES enterprises(id) ON DELETE CASCADE,
     name VARCHAR(255) NOT NULL,
     description TEXT DEFAULT '',
     sort_order INTEGER NOT NULL DEFAULT 0,
     floor_plan_polygon JSONB DEFAULT NULL,
     created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
     updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
 );
 
 CREATE INDEX idx_rz_enterprise ON risk_zones(enterprise_id);
 CREATE INDEX idx_rz_order ON risk_zones(enterprise_id, sort_order);
 ```
 
 **字段说明**：
 
 | 字段 | 类型 | 说明 |
 |------|------|------|
 | name | VARCHAR(255) | 分区名称，如"储罐区"、"生产车间"、"配电房"、"装卸区" |
 | description | TEXT | 分区描述，如面积、功能、主要设备 |
 | sort_order | INTEGER | 排序序号，控制层级树和列表中的显示顺序 |
 | floor_plan_polygon | JSONB nullable | 厂区平面图上的多边形选区坐标。NULL 表示未在平面图上标注 |
 
 `floor_plan_polygon` 存储结构：
 
 ```json
 {
   "points": [
     { "x": 12.5, "y": 34.2 },
     { "x": 45.8, "y": 34.2 },
     { "x": 45.8, "y": 68.1 },
     { "x": 12.5, "y": 68.1 }
   ],
   "color": ""
 }
 ```
 
 - `points` 为多边形顶点数组，每个顶点的 `x` 和 `y` 使用百分比（0~100），与图片的实际像素尺寸解耦。例如 (12.5, 34.2) 表示距离图片左边缘 12.5%、上边缘 34.2% 的位置
 - `color` 初始为空字符串。在可视化总览页中，前端根据分区内最高风险等级自动填充颜色：#ff4d4f（重大）、#fa8c16（较大）、#fadb14（一般）、#52c41a（低）、#d9d9d9（无风险事件）。此字段预留给后续版本做手动颜色覆盖
 
 ### 2.4 风险分析对象表 — risk_objects
 
 ```sql
 CREATE TABLE risk_objects (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     enterprise_id UUID NOT NULL REFERENCES enterprises(id) ON DELETE CASCADE,
     zone_id UUID REFERENCES risk_zones(id) ON DELETE SET NULL,
     name VARCHAR(255) NOT NULL,
     category VARCHAR(100) DEFAULT NULL,
     location VARCHAR(500) DEFAULT NULL,
     location_x FLOAT DEFAULT NULL,
     location_y FLOAT DEFAULT NULL,
     description TEXT DEFAULT '',
     image_url VARCHAR(500) DEFAULT NULL,
     is_risk_point BOOLEAN NOT NULL DEFAULT false,
     sort_order INTEGER NOT NULL DEFAULT 0,
     created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
     updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
 );
 
 CREATE INDEX idx_ro_enterprise ON risk_objects(enterprise_id);
 CREATE INDEX idx_ro_zone ON risk_objects(zone_id);
 CREATE INDEX idx_ro_risk_point ON risk_objects(enterprise_id, is_risk_point)
     WHERE is_risk_point = true;
 ```
 
 **字段说明**：
 
 | 字段 | 类型 | 说明 |
 |------|------|------|
 | zone_id | UUID nullable | 所属分区。NULL 表示该对象不属于任何分区（独立对象） |
 | name | VARCHAR(255) | 对象名称，如"1号储罐"、"冷冻机组"、"10kV高压配电柜" |
 | category | VARCHAR(100) | 对象类别。内置可选值：生产车间、仓库、罐区、配电室、办公楼、装卸区、锅炉房。用户可输入自定义类别 |
 | location | VARCHAR(500) | 文字位置描述，如"厂区西北角"、"车间2楼东侧" |
 | location_x / location_y | FLOAT nullable | 在平面图上的点选坐标（百分比），用于标记对象位置 |
 | description | TEXT | 对象的风险描述 |
 | image_url | VARCHAR(500) nullable | 风险点的实景照片或管线图 URL |
 | is_risk_point | BOOLEAN | 是否标记为风险点。默认 false |
 
 **"风险点"概念说明**：
 
 在中国安全工程实务中，"风险点"是一个关键概念。一个风险点可以是：
 - 一个具体的设备（如"1号储罐"）— 对应 `risk_objects`（is_risk_point=true）
 - 一个场所（如"装卸平台"）— 同样对应 `risk_objects`（is_risk_point=true）
 - 一个工艺流程中的环节（如"焊接工序"）— 可能更适合用 `risk_objects`（category=工艺）表达
 
 本系统中，风险点统一由 `risk_objects` 表的 `is_risk_point` 字段标识。当 `is_risk_point=true` 时：
 - 该对象在平面图上以图钉图标 ◆ 标记（使用 `location_x/y` 坐标）
 - 该对象在列表中以特殊图标区分
 - 该对象可以额外携带 `image_url`（实景照片/管线图/设备铭牌等视觉佐证材料）
 - 用户可通过 `location_x/y` 在平面图上精确点选位置
 
 一个对象可以同时是"分析对象"和"风险点"（即 is_risk_point=true），也可以仅是其中之一。
 
 ### 2.5 风险分析单元表 — risk_units
 
 ```sql

     sort_order INTEGER NOT NULL DEFAULT 0,
     created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
     updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
 );
 
 CREATE INDEX idx_ru_object ON risk_units(object_id);
 CREATE INDEX idx_ru_object_order ON risk_units(object_id, sort_order);
 ```
 
 **字段说明**：
 
 | 字段 | 类型 | 说明 |
 |------|------|------|
 | object_id | UUID | 所属对象，外键级联删除。不可为空——每个单元必须属于一个对象 |
 | name | VARCHAR(255) | 单元名称，如"罐体"、"进油管道"、"冷冻压缩机"、"10kV开关柜" |
 | unit_type | VARCHAR(50) | 单元类型。内置可选值：设备、物料、工艺、电气、特种设备、管道、阀门、仪表、其他 |
 | description | TEXT | 单元描述，如规格参数、工作原理、使用年限 |
 | location | VARCHAR(500) | 具体位置，如"罐体顶部"、"车间B区2号工位" |
 
 `unit_type` 的枚举用于 AI 在生成事件建议和措施建议时做类型匹配：例如 `unit_type=电气` 的单元，AI 优先建议触电/电气火灾类事件和绝缘检测/接地保护类措施。
 
 ### 2.6 风险事件表 — risk_events
 
 ```sql
 CREATE TABLE risk_events (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     unit_id UUID REFERENCES risk_units(id) ON DELETE CASCADE,
     object_id UUID REFERENCES risk_objects(id) ON DELETE CASCADE,
     accident_type VARCHAR(100) NOT NULL,
     description TEXT DEFAULT '',
     trigger_conditions TEXT DEFAULT '',
     consequences TEXT DEFAULT '',
     method_type VARCHAR(20) NOT NULL DEFAULT 'LS'
         CHECK (method_type IN ('LS', 'LEC', 'COAL_LS', 'DIRECT')),
     method_params JSONB NOT NULL DEFAULT '{}'::jsonb,
     risk_level VARCHAR(20) DEFAULT NULL,
     risk_score VARCHAR(50) DEFAULT NULL,
     sort_order INTEGER NOT NULL DEFAULT 0,
     created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
     updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
     CONSTRAINT ck_event_parent CHECK (
         (unit_id IS NOT NULL AND object_id IS NULL)
         OR (unit_id IS NULL AND object_id IS NOT NULL)
     )
 );
 
 CREATE INDEX idx_re_unit ON risk_events(unit_id);
 CREATE INDEX idx_re_object ON risk_events(object_id);
 CREATE INDEX idx_re_risk_level ON risk_events(risk_level);
 ```
 
 **字段说明**：
 
 | 字段 | 类型 | 说明 |
 |------|------|------|
 | unit_id / object_id | UUID nullable | 所属单元或对象，二者必选其一，互斥（CHECK 约束） |
 | accident_type | VARCHAR(100) | 事故类型，按 GB 6441-1986《企业职工伤亡事故分类》标准。详见下文 |
 | description | TEXT | 事故描述——该事故的发生情景和典型后果 |
 | trigger_conditions | TEXT | 触发条件——什么情况下会触发该事故 |
 | consequences | TEXT | 可能后果——事故发生后可能造成的人员伤害和财产损失 |
 | method_type | VARCHAR(20) | 本次评估使用的方法类型，默认 LS |
 | method_params | JSONB | 方法参数，结构因 method_type 而异（见示例） |
 | risk_level | VARCHAR(20) | 计算结果——风险等级，如"重大"、"较大"、"一般"、"低" |
 | risk_score | VARCHAR(50) | 计算结果——分值字符串，如"R=20"、"D=270"、"D=720" |
 
 **`method_params` 示例**：
 
 LS 矩阵：`{"l": 4, "s": 5}` → 后端计算 R=4×5=20 → risk_score="R=20", risk_level="重大"
 LEC 评价法：`{"l": 6, "e": 3, "c": 15}` → 后端计算 D=6×3×15=270 → risk_score="D=270", risk_level="重大"
 直接判定：`{"risk_level": "较大"}` → risk_score="-", risk_level="较大"
 
 **`accident_type` 枚举**（按 GB 6441-1986，共 15 类）：
 
 物体打击、车辆伤害、机械伤害、起重伤害、触电、淹溺、灼烫、火灾、高处坠落、坍塌、锅炉爆炸、容器爆炸、其他爆炸、中毒和窒息、其他伤害
 
 **parent 约束说明**：`ck_event_parent` CHECK 约束确保事件必须挂在单元下（`unit_id` 非空）或对象下（`object_id` 非空），但不能同时挂在两者下。挂在对象下适用于该对象没有子单元的简单场景（如"消防泵房"直接关联"设备故障"事件）；挂在单元下是标准场景（如"1号储罐 → 罐体 → 储罐泄漏"）。

 ## 3. 风险评估方法可视化编辑器
 
 ### 3.1 产品定位与设计目标
 
 这是本模块区别于旧系统最核心的差异化功能。旧系统中风险评估方法（3×3 矩阵，高/中/低）完全硬编码在 `risk_sources_ext.py` 的 `RISK_MATRIX` 字典中，用户无法查看、无法修改、无法新增。本模块将评估方法的所有配置——从参数结构到等级描述到阈值判定表——全部存储在 `risk_assessment_methods.config` 的 JSONB 字段中，通过可视化界面进行维护。
 
 **设计目标**：
 1. 系统预置 LS 和 LEC 两种标准方法供用户直接使用
 2. 用户可通过编辑器查看预置方法的完整配置（只读）
 3. 用户可复制预置方法为企业级副本后自由编辑（参数增删改、阈值调整、等级名称自定义）
 4. 用户可从模板新建自定义方法（选择 LS/LEC/煤矿 LS/空白模板后自由定义）
 5. 编辑过程中右侧面板实时展示评测效果（模拟评分 → 计算等级 → 矩阵高亮）
 6. 每个企业可设定一个默认方法，该企业下所有风险事件创建时自动使用

 ```
 │       ┌───┬───┬───┬───┬───┐       │
 │     1 │低 │低 │低 │一般│一般│       │

 │       ├───┼───┼───┼───┼───┤       │
 │ L   3 │低 │一般│一般│较大│较大│       │
 │       ├───┼───┼───┼───┼───┤       │
 │     4 │一般│一般│较大│较大│[重大]│   │

 │                                    │
 │ 图例：                             │
 │ ██ 重大 (20-25)   ██ 较大 (15-19) │
 │ ██ 一般 (9-14)    ██ 低 (1-8)    │
 └────────────────────────────────────┘
 ```
 
 **实时联动规则**（前端即时反应，无需保存）：
 
 1. **用户点击 L/S 值** → 评测面板立即更新：`R = L × S = {value}` → 查阈值表确定等级和整改建议 → 矩阵中对应的 (L, S) 格子以深色边框高亮，显示 `[等级名]` 标记
 2. **用户修改左侧区域二的参数等级描述** → 评测面板的 L/S 标签和描述文案即时刷新（但矩阵颜色布局不变）
 3. **用户修改左侧区域三的阈值表** → 评测面板的矩阵颜色布局和等级图例即时重新计算并刷新
 4. **用户修改左侧区域一的方法名称** → 评测面板无变化
 
 矩阵热力图的渲染逻辑（前端实现）：
 - 遍历所有 L×S 组合（如 LS 矩阵为 5×5 = 25 个格子）
 - 对每个格子，计算 R = L × S，查当前阈值表获取等级
 - 根据等级的 color 为格子填充背景色
 - 当前评测选中的 (L, S) 格子额外叠加深色边框 + 加粗文字

 ## 4. 五层级风险录入流程（核心）
 
 这是本 PRD 篇幅最长、交互最复杂的一章。五个层级分别对应五张数据表（zone → object → unit → event → measure），每个层级同时支持「手动录入」和「AI 辅助」两种模式。层级树（`RiskHierarchyTree` 组件）是整个流程的导航中枢和唯一入口——用户从树中任意节点旁的 [+] 按钮发起对应层级的创建操作，也可在任何节点上右键编辑或删除。
 
 ### 4.0 AI 融入总则
 
 在进入各层级具体流程之前，先定义 AI 在本模块中的角色和边界。
 
 **AI 角色定义**：AI 始终是"建议者"（advisor），不是"决策者"（decision-maker）。AI 的输出在用户明确点击「采纳」或「确认导入」之前不会写入数据库。用户可以修改、部分采纳或完全忽略 AI 的任何建议。
 
 **AI 三种参与形式**：
 
 | 形式 | 触发方式 | AI 输入 | AI 输出 | 用户操作 |
 |------|----------|---------|---------|----------|
 | **表单内 AI 填充** | 表单中的 [✨ AI 建议] 按钮 | 该表单已填字段 + 父级上下文 + 企业信息 | 当前表单的其余未填字段的建议值 | 逐字段 [✓ 采纳] 或 [✗ 放弃]，采纳后可修改 |
 | **层级批量填充** | 节点旁的 [🤖 智能填充下级] 按钮 | 该节点信息 + 企业信息 | 该节点下所有子层级的完整建议清单 | 逐组勾选 → [全部采纳] 或 [仅采纳勾选]，导入后可修改 |
 | **一键智能导引** | 工具栏 [🚀 智能导引] 按钮 | 用户自然语言描述 + 企业信息 | 完整的分区及其下所有层级的预览 | 审核预览 → 编辑调整 → [确认并导入] |
 
 **AI 上下文来源**（每次 AI 调用携带的信息）：
 - 企业基本信息：`name`、`industry`、`business_scope`、`building_overview`、`employee_count`
 - 企业安全信息：`hazardous_chemicals`、`special_equipment`、`main_equipment_list`、`fire_protection_summary`、`natural_conditions`
 - 当前操作上下文：所属分区/对象/单元的名称、类型、描述
 - 已有数据（去重用）：当前分区下已有的对象名称列表，防止 AI 重复建议
 
 **AI 降级策略**（适用于所有 AI 端点）：
 
 | 场景 | 检测方式 | 用户提示 | 手动功能 |
 |------|----------|----------|----------|
 | AI 未配置 | `AIConfig` 表无记录 | 按钮灰显 + tooltip"请先在系统设置中配置 AI 模型" | 全部正常 |
 | 调用超时（>60s） | HTTP 超时 | Alert"AI 响应超时，请手动录入或稍后重试" | 全部正常 |
 | 返回格式异常 | JSON 解析失败 | Alert"AI 返回格式异常，已记录日志。请手动录入" | 全部正常 |
 | 单日调用次数超限（>200次） | 后端计数器 | Alert"今日 AI 建议次数已用完（200/200），请明天再试或手动录入" | 全部正常 |

 ### 4.4 第四层：添加风险事件（自动评级）
 
 这是整个五层级中最关键、交互最丰富的表单。它直接体现方法可视化编辑器配置的价值——用户在表单中切换评估方法时，参数选项区域动态渲染，右侧预览区实时计算等级。
 
 #### 4.4.1 手动模式 — 表单布局
 
 **入口**：层级树中单元节点（或对象节点）的 [+] → 选择「添加事件」。
 
 **弹出 RiskEventForm 侧边抽屉（宽 560px）**，从上到下分为三段：
 
 **第一段：事件基本信息**
 
 | 序号 | 字段 | 控件 | 必填 | 说明 |
 |:----:|------|------|:--:|------|
 | 1 | 事故类型 | Select（搜索过滤） | ✓ | 15 类按 GB 6441-1986。Select 支持输入关键词快速过滤，如输入"火"→ 过滤出"火灾" |
 | 2 | 事故描述 | TextArea（3行） | | 描述该事故的发生情景和典型后果 |
 | 3 | 触发条件 | TextArea（2行） | | 什么情况下会触发该事故 |
 | 4 | 可能后果 | TextArea（2行） | | 事故发生后可能造成的人员伤害和财产损失 |
 
 **第二段：评估方法参数（动态渲染）**
 
 顶部一个 Segmented 控件（或 Radio.Group 按钮组）用于切换评估方法：
 
 ```
 评估方法：[● LS矩阵] [○ LEC评价] [○ 煤矿LS] [○ 直接判定]
 ```
 
 默认选中企业在 `risk_method_config` 中设定的默认方法。如果企业未设定，则选中系统预置的 LS 矩阵。
 
 根据选中的方法类型，参数区域动态渲染不同的内容：
 
 **当选中 LS 矩阵时**：渲染两个 Radio 卡片组（L 和 S），每个选项以卡片形式展示完整标签和标准描述文本：
 
 ```
 ┌─ 事故发生的可能性（L）──────────────────────────────────────────┐
 │                                                                  │
 │ ○ 1  极不可能                                                    │
 │     有充分有效的防范、控制、监测、保护措施，员工安全意识高，        │
 │     严格执行操作规程，极不可能发生事故                            │
 │                                                                  │
 │ ○ 2  不太可能                                                    │
 │     危害一旦发生能及时发现，并定期进行监测，或现场有防范控制        │
 │     措施并能有效执行，或过去偶尔发生事故或事件                    │
 │                                                                  │
 │ ● 3  可能                                                        │
 │     没有保护措施，或未严格按操作程序执行，或危害的发生容易被发现，  │
 │     或过去曾经发生类似事故或事件                                  │
 │                                                                  │
 │ ○ 4  较可能                                                      │
 │     危害的发生不容易被发现，现场没有检测系统，或控制措施未有效执行  │
 │     或不恰当，或危害常发生在预期情况下发生                        │
 │                                                                  │
 │ ○ 5  极可能                                                      │
 │     在现场没有采取防范、监测、保护、控制措施，或危害的发生不能      │
 │     被发现，或在正常情况下经常发生此类事故或事件                  │
 └──────────────────────────────────────────────────────────────────┘
 ```
 
 S 的结构相同，5 档。注意：每档的标签和描述文本**完全来自** `risk_assessment_methods.config.parameters` 中对应 level 的 `label` 和 `desc` 字段，由前端从 `/methods/{id}` 接口获取后实时渲染。这意味着如果用户自定义了方法（如修改某档描述），事件表单中的选项文字会同步变化。
 
 **当选中 LEC 评价法时**：渲染三个 Radio 组（L、E、C），每个选项的标签和描述同样来自方法 config。L 为 7 档（0.1/0.2/0.5/1/3/6/10）、E 为 6 档（0.5/1/2/3/6/10）、C 为 6 档（1/3/7/15/40/100）。
 
 **当选中直接判定时**：不渲染参数区域，仅显示一个 Select 下拉：「选择风险等级 → 重大/较大/一般/低」。
 
 **第三段：评级结果预览（前端实时计算）**
 
 用户每次选择 L 值或 S 值（或 LEC 的 L/E/C 值）时，预览区域立即在前端本地计算评级结果，无需等待后端响应：
 
 ```
 ┌──────────────────────────────────────────────────────┐
 │ 🟢 风险评级结果                                       │
 │                                                      │
 │ R = L(3) × S(4) = 12  →  一般风险                    │
 │ 整改行动：2年内治理                                   │
 │ 整改期限：2年                                         │
 │                                                      │
 │ 风险矩阵位置（当前值以 ▓ 标记）：                      │
 │                 S                                    │
 │           1   2   3   4   5                           │
 │         ┌───┬───┬───┬───┬───┐                        │
 │       1 │   │   │   │   │   │                        │
 │         ├───┼───┼───┼───┼───┤                        │
 │       2 │   │   │   │   │   │                        │
 │         ├───┼───┼───┼───┼───┤                        │
 │    L  3 │   │   │   │▓▓▓│   │  ← 当前值 L=3, S=4    │
 │         ├───┼───┼───┼───┼───┤                        │
 │       4 │   │   │   │   │   │                        │
 │         ├───┼───┼───┼───┼───┤                        │
 │       5 │   │   │   │   │   │                        │
 │         └───┴───┴───┴───┴───┘                        │
 │                                                      │
 │ 评级依据：L×S 风险矩阵法（5级）                        │
 │ 如需调整评级标准，→ 前往方法配置                       │
 └──────────────────────────────────────────────────────┘
 ```
 
 前端计算使用 `riskMethodEngine.ts` 中的 `computeRiskLS()` 或 `computeRiskLEC()` 函数，这些函数从方法 config 中读取阈值表并判定等级。保存时后端调用 `compute_risk()` 做二次校验，以防前端数据被篡改。
 
 4. 用户确认评级结果后点击「保存」→ 创建 `risk_events` 记录，`risk_level` 和 `risk_score` 由后端计算填充。

 ### 4.6 一键智能导引
 
 针对新建企业或大面积空白区域（没有任何已有层级数据），提供最高效的"一句话生成全部"模式。
 
 **入口**：风险分级管控 Tab 顶部工具栏 → [🚀 智能导引] 按钮。
 
 **前置条件**：用户已配置 AI 模型。如果未配置，按钮灰显，tooltip 提示"请先在系统设置中配置 AI 模型"。
 
 **流程概览**：输入描述 → AI 分析 → 审核预览 → 确认导入，共两步。
 
 **步骤 1 — 描述区域**（Modal，宽 720px）：

 ## 5. 风险管控可视化总览
 
 ### 5.1 定位
 
 可视化总览是企业风险全貌的"驾驶舱"，不用于编辑，只用于浏览、分析和汇报。入口：层级树顶部工具栏的 [📊 可视化总览] 按钮。路由：`/enterprises/:id/risk-management/overview`。
 
 ### 5.2 四象限布局
 
 默认布局为四个区域，左上① 平面图热区、右上② 风险矩阵热力图、左下③ 统计面板、右下④ 层级树紧凑模式。
 
 **① 厂区平面图热区（左上）**：
 
 基于企业上传的 `floor_plan_url`，叠加所有 `risk_zones.floor_plan_polygon` 的半透明多边形。每个多边形的颜色根据该分区内所有 `risk_events` 的最高风险等级自动计算：
 
 | 最高风险等级 | 颜色 | 透明度 |
 |-------------|------|:---:|
 | 重大 | #ff4d4f 红色 | 35% |
 | 较大 | #fa8c16 橙色 | 35% |
 | 一般 | #fadb14 黄色 | 35% |
 | 低 | #52c41a 绿色 | 35% |
 | 无事件 | #d9d9d9 灰色 | 35% |
 
 风险点（`is_risk_point=true` 的对象）以图钉图标 ◆（红色）标注在 `location_x/y` 坐标位置。如果企业未上传平面图，则此区域替换为一句话提示"尚未上传厂区平面图，上传后可在此处查看风险热区。→ [上传平面图]"，链接到企业编辑页。
 
 交互：点击多边形 → 高亮对应分区 → 右侧层级树滚动到对应节点。点击图钉 ◆ → Popover 弹出：风险点名称、图片缩略图（如有）、关联事件数、最高风险等级。支持鼠标滚轮缩放和拖拽平移。
 
 **② 风险矩阵热力图（右上）**：
 
 根据企业默认评估方法动态渲染矩阵：
 
 - LS 矩阵：5×5 矩阵，行=L(1-5)，列=S(1-5)，每格显示该 (L,S) 组合的事件数量
 - LEC 矩阵：自适应该方法的 L/E/C 级别数，每格显示对应组合的 L 值和 C 值下的事件数
 
 每格背景色根据该组合计算出的 R 值对应等级染色（从方法 config 的 `risk_thresholds` 读取）。数字 = 落在该组合的事件总数。
 
 交互：悬停格子 → Tooltip 列出这些事件的名称和所属分区。点击格子 → 右侧层级树临时过滤仅显示这些事件（加筛选标记）。
 
 **③ 统计面板（左下）**：
 
 使用 ECharts 或 Recharts 渲染两个图表 + 汇总数字：
 
 - **环形图**：风险等级分布（重大/较大/一般/低 的数量和百分比）
 - **横向柱状图**：事故类型 Top 5（按事件数降序）
 - **汇总数字行**（四列）：总分区数 · 总对象数 · 总事件数 · 总措施数 · 已实施措施占比（implemented / total × 100%）
 
 **④ 层级树紧凑模式（右下）**：
 
 节点高度压缩（无操作按钮），仅显示层级结构 + 风险等级颜色标签（重大/较大/一般/低 等带颜色 Tag）。功能：点击节点 → 平面图热区联动高亮该节点所属分区。双击节点 → 跳转到主录入页并自动定位到该节点。
 
 ### 5.3 视图切换
 
 顶部工具栏提供三个按钮，用于切换四象限的显示优先级：
 
 | 视图 | 说明 |
 |------|------|
 | 四象限 | 默认，如上图，所有区域均分 |
 | 平面图优先 | 平面图占全宽（顶部 60%），统计面板右侧，层级树底部折叠 |
 | 数据优先 | 层级树全高左栏（40% 宽），矩阵+统计右侧，平面图折叠为底部缩略条 |
 
 ### 5.4 管控拓扑图
 
 在右下角的层级树区域，工具栏增加切换按钮：「[层级树] [管控拓扑图]」。管控拓扑图以**组织架构图**的视觉形式，将五级风险管控体系（分区 → 对象 → 单元 → 事件）呈现为自上而下的树状拓扑结构，每个节点的颜色反映其风险严重程度。
 
 拓扑图从上到下分 5 层：企业总览 → 分区 → 对象 → 单元 → 事件。每个节点为圆角矩形卡片，内部显示名称、风险等级颜色条（左边框）、事件计数。节点颜色从子节点向上传播：父节点的颜色条 = 所有子孙节点中最高的风险等级颜色。连线使用正交连线（组织架构图风格），浅灰色。风险点（is_risk_point=true）的节点名称旁显示 ◆ 图标。
 
 交互：鼠标滚轮缩放（0.5x ~ 2x），拖拽平移，点击节点高亮并联动左上角平面图热区，悬停显示详细信息（完整名称、风险等级、事件列表预览、措施数量），双击跳转主录入页。每个父节点可折叠/展开子节点。底部固定图例（颜色 + ◆ 标记）。
 
 与层级树的互补关系：层级树信息密度高，适合精确查找和编辑；拓扑图空间感强，适合汇报展示和快速识别风险集中区域。用户首次打开总览时默认显示层级树，可切换到拓扑图，最后一次选择保存在浏览器 localStorage。

 ## 8. 业务逻辑
 
 ### 8.1 评级计算流程
 
 1. 用户选择方法类型 + 输入参数 → 前端 `riskMethodEngine.ts` 本地计算预览
 2. 保存时提交 `method_type` + `method_params` → 后端 `compute_risk()` 二次计算
 3. 查询链路：`GET /methods` 查企业级活跃方法 config（`enterprise_id=当前企业` + `is_active=true` + `method_type=入参`）→ 未命中则查系统级（`enterprise_id IS NULL` + 同样条件）
 4. 从 config 读取 `formula`、`parameters`、`risk_thresholds`
 5. 计算分值（LS: R=L×S, LEC: D=L×E×C, DIRECT: 无计算）
 6. 遍历阈值表找到匹配区间 → 返回 `risk_level`, `risk_score`, `action`, `deadline`
 7. 写入 `risk_events.risk_level` 和 `risk_score`
 
 ### 8.2 方法配置更新后的事件重算
 
 当用户修改了方法的阈值表或参数定义后，已有事件的 `risk_level` 不会自动刷新（因为可能覆盖人工确认的结果）。用户在层级树中看到事件节点旁有一个 [🔄 重新评级] 按钮，点击后用最新方法 config 重算。
 
 ### 8.3 级联删除规则
 
 | 删除 | 级联影响 |
 |------|----------|
 | 分区 | → 所有对象 → 所有单元 → 所有事件 → 所有措施 |
 | 对象 | → 所有单元 → 所有事件 → 所有措施 |
 | 单元 | → 所有事件 → 所有措施 |
 | 事件 | → 所有措施 |
 | 措施 | 无级联 |
 
 每次级联删除前弹出 Modal 确认，显示"将同时删除 X 个对象、Y 个单元、Z 个事件、W 条措施，确认？"。

 ## 12. 非功能性需求
 
 - `/hierarchy` 端点对 ≤100 对象、≤500 事件的企业响应 < 2s
 - 层级树节点 > 200 时启用虚拟滚动（Ant Design Tree 的 `virtual` 属性）
 - AI 所有端点 60s 超时，单用户每日调用上限 200 次（后端 Redis 计数器）
 - 平面图上传 > 5MB 时前端压缩至 ≤ 1920px 宽后上传
 - 方法编辑器阈值表保存前端校验区间不重叠 + 区间连续性提示
