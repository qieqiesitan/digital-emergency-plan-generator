# 法规库管理优化实施方案
编写日期：2026-07-13 | 状态：待评审

## 一、当前问题诊断

### 1.1 新增法规流程痛点
- 用户粘贴全文 → 等 AI 解析 → 预览 → 入库，流程线性但缺少智能校验
- 无查重机制：同名/同编号法规可重复入库
- 无冗余提示：不会提示"该法规已存在"或"与已有法规覆盖范围重叠"
- 解析字段有时不完整（编号、日期等），需手动补全

### 1.2 管理功能痛点
- 列表只有搜索+筛选，缺乏批量操作（批量废止、批量导出）
- 法规详情页功能单一，缺少版本对比、修订历史可视化
- 废止操作简单粗暴，无关联影响提示（废了这条，哪些预案会受影响？）

### 1.3 图谱控制台报错
- Unable to preventDefault inside passive event listener invocation
- 根因：滚轮缩放事件中调了 e.preventDefault()，但浏览器默认将 wheel 事件注册为 passive
- 影响：缩放时页面同时滚动，体验差

### 1.4 其他控制台警告
- [antd: Card] bodyStyle deprecated → styles.body
- [antd: message] Static function can not consume context

## 三、详细设计

### 3.1 P0：新增法规自动查重

**方案：** 入库前，用法规编号 + 全称模糊匹配双重校验。

**后端改动：**

1. POST /api/v1/regulations/check-duplicate — 新增查重端点
   - 入参：{ code, full_name }
   - 精确匹配 code（忽略大小写和空格）
   - 若 code 未匹配，用 full_name 做 difflib.SequenceMatcher 相似度 > 0.7
   - 返回：{ duplicate: bool, matches: [{ id, code, full_name, similarity }] }

2. POST /api/v1/regulations 入库接口增加查重校验
   - 若重复 → 返回 409 Conflict + 匹配列表
   - 不重复 → 正常入库

**前端改动：**

1. RegulationForm.tsx 解析成功后预览阶段：
   - 自动调查重接口
   - 无重复 → 绿色 checkmark
   - 有重复 → 红色警告卡片 + 匹配列表 + "仍要入库"按钮

**工作量：** 后端 1 端点 + 2 处改动，前端 1 API + UI，约 2h。

---

### 3.2 P0：修复图谱控制台报错

**方案：** useEffect + ref.addEventListener("wheel", handler, { passive: false })

在 RegulationGraph.tsx 中：
- 找到 SVG onWheel 处理（约 156 行）
- 改用 useEffect 手动注册 non-passive wheel 事件
- 组件卸载时 removeEventListener 清理

**工作量：** 1 处改动，约 30min。

---

### 3.3 P0：修复 antd 废弃 API 警告

**Card bodyStyle → styles.body：**
- RegulationList.tsx / RegulationGraph.tsx 中所有 Card bodyStyle 改为 styles: { body: {...} }

**message 静态方法 → App.useApp()：**
- 根组件包裹 App，或页面级用 App.useApp().message

**工作量：** 3 处 bodyStyle + 1 处 message，约 30min。

## 五、风险与边界

- 查重依赖法规编号规范性——若 AI 解析不出编号，只能靠名称相似度
- 相似度阈值 0.7 可能需要根据实际数据调参
- 图谱修改保留旧拖拽+缩放逻辑，只改事件注册方式
